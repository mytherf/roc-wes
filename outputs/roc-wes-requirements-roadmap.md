# ROC-WES 需求分析与 Roadmap

> 产品定位：仓储自动化 Web SCADA 组态平台
> 三大支柱：**仿真演示 → 实时监控 → 运行执行**
> 基线版本：当前代码库（2026-07-31）
> 目标用户：仓储自动化集成商（售前/验证）、设备/电气工程师（轻量监视）

## 三、Phase 1 — MVP：可交付演示工具

> 目标：让集成商售前能「开箱搭画面 → 连真设备 → 给客户演示」，无需开发介入。
> 周期估算：4-6 周（单人）

## 七、Phase 1 功能点详细规格

### S-10 画面模板库

**用户故事**：作为集成商售前，我想从预置模板快速创建一套看起来专业的监控画面，这样我不需要从零摆放 50 个设备就能给客户演示。

**功能描述**：
- 新建工程时弹出模板选择（空白 / AS/RS 立库 / 输送分拣线 / AGV 调度区 / 综合总览）
- 模板包含：设备布局坐标 + 预绑定模拟点位 + 默认 transform + 推荐数据源配置
- 模板以 JSON 文件形式存放在 `src/templates/` 目录，可扩展
- 选择模板后自动创建对应数据源（演示模式）

**验收标准**：
- Given 用户点击「新建工程」，When 选择「AS/RS 立库」模板，Then 画布出现堆垛机+货架+输送线布局，所有节点有模拟数据驱动
- Given 模板已加载，When 用户切换到真实模式，Then 数据源地址变为网关地址，绑定关系不变

---

### S-11 一键演示模式

**用户故事**：作为售前，我想点一个按钮就让整个画面「动起来」，这样客户来访时我不需要手忙脚乱地配置数据源。

**功能描述**：
- 工具栏新增「▶ 演示」按钮（区别于「▶ 运行」）
- 点击后：① 所有数据源强制切为演示模式 ② 进入全屏运行态 ③ 顶部浮动提示条「演示模式 · 按 ESC 退出」
- 演示模式下数据源监控面板显示「演示」标签
- ESC 退出回到编辑器，数据源模式恢复

**验收标准**：
- Given 画布有 ≥3 个已绑定节点，When 点击「演示」，Then 2s 内进入全屏运行态且所有节点数据动态刷新
- Given 处于演示运行态，When 按 ESC，Then 回到编辑器，数据源配置恢复为演示前状态

---

### M-10 告警中心面板

**用户故事**：作为设备工程师，我想在运行态看到一个集中的告警列表，这样我不需要盯着每个设备就能知道哪里出了问题。

**功能描述**：
- 运行态底部可折叠告警栏（默认收起，有新告警时自动展开+角标计数）
- 告警条目：时间戳 | 设备名 | 级别图标 | 告警内容 | 当前值
- 操作：逐条确认（✓）/ 全部确认 / 清除已确认
- 未确认告警持续高亮，确认后降级为灰色
- 告警数据仅运行时内存维护（Phase 1 无后端），刷新后清空

**验收标准**：
- Given 节点事件规则触发（值 > 阈值），When 上升沿到达，Then 1s 内告警栏出现新条目 + 角标 +1
- Given 告警栏有 3 条未确认告警，When 点击「全部确认」，Then 所有条目变为已确认样式，角标归零

---

### R-10 多工程管理

**用户故事**：作为工程师，我想管理多个项目的画面（A 仓库 / B 仓库 / 演示用），这样我不需要反复导入导出 JSON。

**功能描述**：
- 新增工程列表页（`/projects` 路由）作为应用首页
- 工程卡片：名称 + 缩略图（画布截图）+ 最后编辑时间 + 节点数
- 操作：新建（空白/模板）/ 打开 / 重命名 / 删除（二次确认）/ 导出
- 存储：每个工程独立 localStorage key（`roc-wes-project-{id}`）
- 编辑器顶栏显示当前工程名，可点击返回列表

**验收标准**：
- Given 工程列表页，When 点击「新建」并选择空白，Then 创建新工程并进入空画布编辑器
- Given 已有 3 个工程，When 删除其中一个，Then 确认后该工程从列表消失，其余不受影响
- Given 打开工程 A 编辑后返回列表，When 打开工程 B，Then 画布显示 B 的内容，A 的修改已保存

### E-10 统一部署编排

**用户故事**：作为部署人员，我想一条命令启动所有服务，这样我不需要记住 6 个 npm run 命令的顺序。

**功能描述**：
- 提供 `docker-compose.yml`：前端（nginx 静态）+ modbus-gateway + s7-gateway + opc-gateway + 三个仿真器（可选 profile）
- 提供 `scripts/start-all.sh`（开发环境）：并行启动 dev server + 全部网关
- 网关通过环境变量配置端口与设备地址
- 健康检查端点：每个网关暴露 `/health`

**验收标准**：
- Given 干净环境，When 执行 `docker compose up`，Then 60s 内前端可访问 + 三个网关健康检查返回 200
- Given 开发环境，When 执行 `npm run dev:all`，Then 前端 + 网关 + 仿真器全部启动，控制台统一输出日志

## 十、风险与决策点

| 风险 | 影响 | 缓解 |
|------|------|------|
| Phase 2 引入后端后架构复杂度陡增 | 前端团队可能缺乏后端经验 | 选最简方案（Fastify + SQLite），不过度设计 |
| 下行控制涉及设备安全，出错代价高 | 误操作可能导致设备损坏/人员伤害 | Phase 3 启动前做安全评审；互锁+确认+审计三重保护 |
| 工业协议兼容性（不同品牌 PLC 差异） | 现场调试周期长 | 先锁定 Siemens S7-1200 + Modbus TCP 两类主流设备 |
| 产品定位升级（监控→控制）需客户验证 | 投入大但市场不确定 | Phase 2 交付后收集 3-5 个客户反馈再决定 Phase 3 范围 |

**关键决策点**：Phase 2 完成后，根据客户反馈决定 Phase 3 是走「轻量 WCS 调度」还是「纯监控深化（报表/分析/移动端）」路线。
