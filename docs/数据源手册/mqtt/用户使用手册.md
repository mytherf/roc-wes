# MQTT 数据源 · 用户使用手册

> 适用版本：roc-wes 编辑器 ｜ 数据源类型标识：`mqtt` ｜ 内置模拟地址：`ws://localhost:8083`

## 一、简介

MQTT 是物联网领域最主流的轻量级「发布/订阅」消息协议，专为低带宽、不稳定网络设计。设备把数据「发布（publish）」到某个主题（topic），任何「订阅（subscribe）」了该主题的客户端都能收到。它天然支持一对多分发、主题通配、遗嘱消息等能力，非常适合海量设备接入。

浏览器无法直接使用原生 MQTT（基于 TCP），因此编辑器通过 **MQTT over WebSocket** 连接 broker——地址以 `ws://`（或加密 `wss://`）开头。编辑器内部使用 mqtt.js 客户端，**点ID就是 MQTT 主题**。

## 二、适用场景

- 现场设备/网关已通过 MQTT 上报数据（如 EMQX、Mosquitto、阿里云 IoT 等 broker）。
- 需要一对多分发：同一份设备数据被多个画面/节点消费。
- 海量测点、弱网环境，希望用主题层级（如 `factory/line1/temp`）组织数据。

若只是单一服务端推送少量数据，[WebSocket](../websocket/用户使用手册.md) 或 [SSE](../sse/用户使用手册.md) 更简单。

## 三、快速开始（演示模式，3 步上手）

开发环境（`npm run dev`）自动启动内置 MQTT broker（aedes），浏览器经 `ws://localhost:8083` 接入。

**第 1 步：创建数据源**

「🔌 数据源管理」→「＋ 新增数据源」：

- 名称：`内置MQTT模拟源`
- 类型：`MQTT`
- 地址：`ws://localhost:8083`（点「填入」自动补全；注意是 broker 的 WebSocket 地址，不带主题）

**第 2 步：绑定节点**

选中节点 → 「数据绑定」标签页：

- 数据源：`内置MQTT模拟源`
- 点ID：`device/pump/01/status`（这就是要订阅的 MQTT 主题）
- 转换函数：留空

**第 3 步：观察数据**

节点显示离散档位值，在 `0 / 25 / 50 / 75 / 100` 之间每约 3 秒切换一次（方波/阶梯），模拟设备档位。

## 四、配置项说明

| 字段 | 说明 | 示例 |
| --- | --- | --- |
| 名称 | 数据源显示名 | `车间IoT-Broker` |
| 类型 | `MQTT` | — |
| 地址 | broker 的 WebSocket 接入地址（`ws://`/`wss://`） | `wss://broker.example.com:8084/mqtt` |
| 备注 | 可选 | `EMQX 公网接入点` |

> 地址只填 broker 接入点，**不要带主题**；主题在节点「点ID」里填。MQTT over WebSocket 由 mqtt.js 原生支持，**无需独立网关**。

## 五、点ID（MQTT 主题）填写规则

点ID即 MQTT 主题，遵循 MQTT 主题规范：

- 用 `/` 分层，如 `factory/line1/conveyor/speed`。
- 支持通配符：`+`（单层）与 `#`（多层），如 `factory/+/temp`、`factory/#`。
- 内置模拟服务只对**具体主题**（不含通配符）主动发布数据；接真实 broker 时通配符订阅可正常接收。

设备发布的消息载荷（payload）为 JSON 时，编辑器取 `value`（兼容 `data`，再兼容整个载荷）作为数值：

```json
{ "value": 75, "timestamp": 1730000000000, "quality": "good" }
```

## 六、实际案例：泵站运行档位监控

**场景**：现场 3 台泵通过 MQTT 上报运行档位到 broker `wss://iot.factory.com:8084/mqtt`，主题分别为 `pump/1/level`、`pump/2/level`、`pump/3/level`，载荷 `{"value": 0|1|2|3}`（0=停止，3=满载）。需要在画布上显示每台泵档位，并把数字档位映射成中文状态。

**操作步骤**：

1. 数据源管理 → 新增：名称 `泵站Broker`，类型 `MQTT`，地址 `wss://iot.factory.com:8084/mqtt`。
2. 放置 3 个状态标签节点，绑定该数据源，点ID分别填 `pump/1/level`、`pump/2/level`、`pump/3/level`。
3. 转换函数填：`(raw) => ['停止','低速','中速','满载'][raw] ?? '未知'`，把数字档位转成中文。

**预期效果**：3 个标签实时显示对应泵的中文运行状态；设备发布新档位即刻刷新。

## 七、接入自己的 MQTT broker

1. 确保 broker 开启了 **WebSocket 接入**（如 EMQX 默认 `8083`/`8084`，Mosquitto 需配置 `listener ... protocol websockets`）。
2. 数据源地址填该 WebSocket 接入点（`ws://host:port` 或带 path）。
3. 节点点ID填要订阅的主题；设备向该主题发布 JSON（含 `value`）即可被解析。
4. 需要鉴权时，目前通过地址或 mqtt.js 连接参数扩展（见开发手册）。

## 八、常见问题

**Q：连接不上 broker？**
确认：① 地址是 WebSocket 接入点（`ws://`/`wss://`）而非原生 TCP 的 `mqtt://`/`1883`；② broker 已开启 WebSocket 监听；③ 加密页面（https）必须用 `wss://`，否则浏览器会拒绝混合内容。

**Q：订阅了通配符主题但内置模拟没数据？**
内置模拟服务只对具体主题发布。接真实 broker 时通配符订阅正常；本地演示请用具体主题。

**Q：断网后会重连吗？**
会。mqtt.js 客户端配置了 3 秒自动重连（`reconnectPeriod: 3000`），重连成功后自动重新订阅之前的所有主题。

## 九、注意事项

- 生产环境用 `wss://` 加密，并启用 broker 的用户名密码/Token 鉴权，避免匿名访问。
- 主题层级设计要规整，便于通配符批量订阅与权限控制。
- 高频遥测建议在设备侧或 broker 规则引擎做节流，避免画面端压力过大。
