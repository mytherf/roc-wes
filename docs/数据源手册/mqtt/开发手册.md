# MQTT 数据源 · 开发手册

> 面向维护、调试或扩展 MQTT 数据接入的开发者。数据源类型标识：`mqtt`。

## 一、架构与数据流

浏览器经 **MQTT over WebSocket**（mqtt.js）连接 broker，点ID即 MQTT 主题，**无需自研网关**：

```
┌────────────┐  subscribe(topic)   ┌─────────────┐  MQTT over WS (mqtt.js)  ┌────────────┐
│ X6 节点     │ ──────────────────▶ │ MqttService │ ───────────────────────▶ │ MQTT broker │
│ node.data   │                     │             │ ◀════ publish(topic) ═════ │ (aedes 等)  │
│  .value     │ ◀────────────────── │             │   payload: {value,...}    └────────────┘
└────────────┘   DataPoint 回调      └─────────────┘
```

## 二、核心类型定义

复用统一的 `DataPoint` / `IDataService` / `DataBindingConfig`（`src/services/DataService.ts`）。数据源实例 `DataSource.type = 'mqtt'`，`config` 通常为空（如需鉴权可扩展）。

## 三、前端 Service 实现

文件：`src/services/MqttService.ts`，基于 `mqtt`（mqtt.js）。

```ts
import mqtt from 'mqtt'

constructor(url: string) {
    this.client = mqtt.connect(url, { reconnectPeriod: 3000, connectTimeout: 5000 })

    this.client.on('connect', () => {
        this.connected = true
        // 重连后重新订阅之前的所有主题
        for (const [topic] of this.callbacks) this.client.subscribe(topic)
    })

    this.client.on('message', (topic, payload) => {
        const data = JSON.parse(payload.toString())
        const point: DataPoint = {
            id: topic,
            value: data.value ?? data.data ?? data,   // 兼容三种载荷
            timestamp: data.timestamp || Date.now(),
            quality: data.quality || 'good',
        }
        for (const cb of this.callbacks.get(topic) || []) cb(point)
    })
}

subscribe(pointId: string, callback: DataCallback): void {
    if (!this.callbacks.has(pointId)) this.callbacks.set(pointId, [])
    this.callbacks.get(pointId)!.push(callback)
    if (this.connected) this.client.subscribe(pointId)
}
```

要点：

- **点ID = 主题**：`callbacks: Map<topic, DataCallback[]>`，订阅即 `client.subscribe(topic)`。
- **自动重连 + 重订阅**：`reconnectPeriod: 3000`；`connect` 事件里遍历 `callbacks` 重新订阅。
- **载荷兼容**：`value ?? data ?? 整个载荷`，既能解析结构化 JSON，也能接收纯数值载荷。
- **通配符**：mqtt.js 支持 `+`/`#`；但回调按「精确 topic」匹配 `callbacks`，通配符订阅收到的具体主题需在 `callbacks` 中有对应键才会分发（见扩展指南）。
- `disconnect()` 调用 `client.end(true)` 强制断开并清空回调。

## 四、数据格式与点ID约定

| 方向 | 内容 | 说明 |
| --- | --- | --- |
| 前端 → broker | `SUBSCRIBE <topic>` | 订阅主题（mqtt.js 封装） |
| 设备 → broker → 前端 | `PUBLISH <topic>` payload `{"value", "timestamp"?, "quality"?}` | 数据消息 |

点ID遵循 MQTT 主题规范（`/` 分层，支持 `+`/`#` 通配）。

## 五、内置模拟服务

文件：`mock/server.ts` 的 `startMqttServer()`，使用 `aedes` broker，同时提供 TCP（1883）与 WebSocket（8083）接入：

```ts
const broker = await Aedes.createBroker()      // 必须用 createBroker() 初始化 persistence
const tcpServer = net.createServer(broker.handle)
safeListen(tcpServer, MOCK_PORTS.mqttTcp, 'MQTT-TCP')   // 1883

const httpServer = http.createServer()
const wss = new WebSocketServer({ server: httpServer })
wss.on('connection', (conn, req) => {
    const stream = createWebSocketStream(conn)
    broker.handle(stream, req)                 // WS 桥接到 broker
})
safeListen(httpServer, MOCK_PORTS.mqttWs, 'MQTT-WS')    // 8083

// 记录订阅的具体主题，周期性发布离散档位数据
const topics = new Set<string>()
broker.on('subscribe', (subscriptions) => {
    for (const s of subscriptions)
        if (!s.topic.includes('#') && !s.topic.includes('+')) topics.add(s.topic)
})
setInterval(() => {
    const t = Date.now()
    for (const topic of topics) {
        const payload = JSON.stringify({ value: mqttValue(topic, t), timestamp: t, quality: 'good' })
        broker.publish({ topic, payload, qos: 0, retain: false, cmd: 'publish', dup: false }, () => {})
    }
}, 1500)
```

> 关键坑：必须用 `Aedes.createBroker()`（会 await 初始化 persistence 并置 `closed=false`）；直接 `new Aedes()` 时 broker 处于 closed，CONNECT 会被静默丢弃导致 connack 超时。

数据生成算法（`mock/generators.ts`）——离散设备档位，在 `[0,25,50,75,100]` 间每 3 秒步进切换：

```ts
const MQTT_STATES = [0, 25, 50, 75, 100]
export function mqttValue(pointId: string, t: number): number {
  const step = Math.floor(t / 3000)
  return MQTT_STATES[(step + hashInt(pointId)) % MQTT_STATES.length]
}
```

## 六、路由与节点绑定机制

`useDataService.ts`：

```ts
case 'mqtt':
    service = new MqttService(sourceUrl)
    break
```

绑定回调把 `point.value`（经可选 `transform`）写入 `node.data.value`，与其余数据源一致。

## 七、扩展指南

- **鉴权接入**：在 `mqtt.connect(url, { username, password, clientId })` 中补充；可将这些字段加入数据源 `config`，由 `useDataService` 透传给 `MqttService` 构造函数。
- **通配符订阅分发**：当前 `message` 回调按精确 topic 命中 `callbacks`。若需让通配符订阅（如 `factory/#`）把具体主题分发给订阅者，可在 `message` 中对 `callbacks` 的键做 MQTT 主题匹配（实现 `+`/`#` 匹配算法）后分发。
- **QoS / retain**：订阅时 `client.subscribe(topic, { qos: 1 })`；发布侧按需设置 retain。
- **修改模拟数据**：编辑 `mqttValue()` 或调整发布间隔（当前 1500ms）。

## 八、调试与验证

1. `npm run dev`，控制台出现 `[mock] MQTT broker 已启动: tcp://localhost:1883, ws://localhost:8083`。
2. 浏览器控制台动态验证：

```js
const { MqttService } = await import('http://localhost:5173/src/services/MqttService.ts')
const svc = new MqttService('ws://localhost:8083')
svc.subscribe('device/pump/01/status', p => console.log(p.value))
// 每约 1.5s 输出离散档位（0/25/50/75/100）；验证完 svc.disconnect()
```

3. 用 `mosquitto_pub/sub` 经 TCP 验证 broker：

```bash
mosquitto_sub -h localhost -p 1883 -t 'device/pump/01/status'
```
