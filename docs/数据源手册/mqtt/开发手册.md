# MQTT 数据源 · 开发手册

> 面向维护、调试或扩展 MQTT 数据接入的开发者。数据源类型标识：`mqtt`。

## 一、架构与数据流

MQTT 数据接入统一由桌面端 Rust 网关接管（**真实模式与演示模式同一条 IPC 链路**，WebView 不再直连 broker）：真实模式由 Rust 网关的 `MqttAdapter`（rumqttc）连接 broker，支持 `mqtt://`（原生 TCP）与 `ws://`（MQTT over WebSocket）两种地址；演示模式由 `DemoAdapter`（`profile = Mqtt`，离散档位）生成数据（不占用端口）：

```
真实模式：
┌────────────┐  subscribe(pointId)  ┌───────────────────┐   Tauri IPC    ┌───────────────────┐  MQTT (rumqttc)  ┌────────────┐
│ X6 节点     │ ────────────────▶ │ IpcGatewayService │ ────────────▶ │ Rust MqttAdapter  │ ═════════════▶ │ MQTT broker │
│  .value     │ ◀──────────────── │  (src/services)   │ ◀──────────── │ (gateway-web)     │ ◀═ publish ═══ │ (EMQX 等)  │
└────────────┘  DataPoint 回调      └───────────────────┘ telemetry 事件  └───────────────────┘                 └────────────┘

演示模式：链路相同，仅适配器换为 Rust DemoAdapter（离散档位生成，不建立 MQTT 连接）
```

## 二、核心类型定义

复用统一的 `DataPoint` / `IDataService` / `DataBindingConfig`（`src/services/DataService.ts`）。数据源实例 `DataSource.type = 'mqtt'`，`config` 通常为空（如需鉴权可扩展）。

## 三、Rust 适配器实现

文件：`src-tauri/crates/gateway-web/src/mqtt.rs`（`MqttAdapter`，基于 rumqttc）。原前端 `src/services/MqttService.ts`（mqtt.js 浏览器直连）已随网关统一移除，`mqtt` npm 依赖一并清理。

关键机制（「后台事件循环任务 + 最新值缓冲」模式）：

- **建连**：`connect()` 用 `MqttOptions::parse_url` 解析地址（`mqtt://` 或 `ws://`），生成唯一 client_id（避免 broker 互踢），spawn eventloop 任务驱动收发。
- **订阅差量同步**：`read(point_ids)` 每 tick 对比上次订阅集，新增/移除的点位分别 `subscribe`/`unsubscribe` 主题过滤器（QoS 1）。
- **通配符分发**：收到 `PUBLISH` 时用 MQTT 通配符匹配（`+` 单层 / `#` 多层，`common.rs` 的 `topic_matches`）命中订阅过滤器，遥测 `point_id` 记为**订阅过滤器**（与节点绑定语义一致）。
- **载荷兼容**：JSON 载荷取 `value ?? data`，两者都缺时兜底整个 JSON；非 JSON 载荷忽略。
- **断线重连**：eventloop 出错退出时置 `dead` 标志，下次 `read()` 报错触发网关引擎指数退避重连（2s→30s），重连后按当前订阅集重新订阅。

要点：点ID 即主题过滤器（`/` 分层，支持 `+`/`#` 通配）。

## 四、数据格式与点ID约定

| 方向 | 内容 | 说明 |
| --- | --- | --- |
| Rust 网关 → broker | `SUBSCRIBE <topic-filter>`（QoS 1） | 订阅主题过滤器 |
| 设备 → broker → Rust 网关 | `PUBLISH <topic>` payload `{"value", "timestamp"?, "quality"?}` | 数据消息 |

点ID遵循 MQTT 主题规范（`/` 分层，支持 `+`/`#` 通配）。

## 五、内置模拟引擎（演示模式）

Node 版内置模拟 broker（原 `mock/server.ts` 的 `startMqttServer()`，aedes，TCP 1883 / WS 8083）已移除，`aedes`/`ws` 等 devDependencies 一并清理。演示模式改由桌面端 Rust 网关内置实现：`src-tauri/crates/gateway-demo/src/lib.rs` 的 `DemoAdapter`（`profile = Mqtt`），不监听任何端口、不建立 MQTT 连接，由 gateway-engine 会话任务按轮询周期读取后经 Tauri IPC 事件推送。

数据生成算法——离散设备档位，在 `[0, 25, 50, 75, 100]` 间每 3 秒窗口步进切换（与原 Node 版 `mqttValue()` 行为一致）：

```rust
const MQTT_STATES: [f64; 5] = [0.0, 25.0, 50.0, 75.0, 100.0];
fn mqtt_value(point_id: &str, now_ms: u64) -> f64 {
    let step = now_ms / 3000;
    MQTT_STATES[((step + hash_u64(point_id)) % MQTT_STATES.len() as u64) as usize]
}
```

## 六、路由与节点绑定机制

`useDataService.ts`：演示/真实模式统一路由到 `IpcGatewayService`——演示模式配置为 `{ kind:'demo', profile:'mqtt' }`；真实模式配置为 `{ kind:'mqtt', url, pollIntervalMs }`（url 支持 `mqtt://host:1883` 与 `ws://host:8083` 两种接入点）。

绑定回调把 `point.value`（经可选 `transform`）写入 `node.data.value`，与其余数据源一致；数据延迟 ≤ pollIntervalMs。

## 七、扩展指南

- **鉴权接入**：rumqttc 支持 `MqttOptions::set_credentials(username, password)`；可在 `gateway-web/src/mqtt.rs` 的 `connect()` 中补充，并将字段加入数据源 `config` 由 `deviceConfig.ts` 透传。
- **通配符订阅分发**：Rust 适配器已内置 `+`/`#` 匹配（`common.rs` 的 `topic_matches`）：收到具体主题的发布时命中订阅过滤器即分发，遥测 point_id 为过滤器。
- **QoS / retain**：订阅固定 QoS 1（AtLeastOnce）；发布侧按需设置 retain。
- **修改模拟数据**：编辑 `gateway-demo` 的 `mqtt_value()` 或 `MQTT_STATES` 档位。

## 八、调试与验证

1. 真实模式：`npx tauri dev` 后在数据源对话框填入自己 broker 的接入点（`mqtt://host:1883` 或 `ws://host:8083`），绑定主题观察推送（Rust 侧日志 `gateway_web` 目标可见连接/订阅记录）。
2. 演示模式：`npx tauri dev` 启动桌面应用，新建 MQTT 演示数据源（无需地址，`config.demo = true` 标识；可在「演示波形」中更换波形档位），绑定具体主题后应看到 `0/25/50/75/100` 离散档位每约 3 秒切换。
3. 演示波形逻辑可用 Rust 单测验证：`cargo test -p gateway-demo`。
