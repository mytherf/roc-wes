# SSE 数据源 · 用户使用手册

> 适用版本：roc-wes 编辑器（桌面版） ｜ 数据源类型标识：`sse` ｜ 演示标识地址：`http://localhost:8082/sse`（仅作演示模式标识，无对应本地服务）

## 一、简介

SSE（Server-Sent Events，服务端推送事件）是一种基于 HTTP 的「服务端单向推送」协议。浏览器通过一个普通的 HTTP 连接订阅后，服务端可以持续不断地把数据推下来。相比 WebSocket，它**更轻量、天然走 HTTP（防火墙友好）、浏览器自带断线自动重连**；相比 HTTP 轮询，它无需反复发请求、实时性更好。

限制是只能服务端→浏览器单向推送（不能双向通信），且基于 HTTP/1.1 时每个域名有并发连接数限制。对监控画面这种「只读数、不下发」的场景非常合适。

## 二、适用场景

- 服务端单向推送实时数据，且希望省去自己实现重连逻辑（浏览器自动重连）。
- 需要走标准 HTTP 端口（80/443）、穿透防火墙/代理，不想额外部署 WebSocket。
- 实时趋势、进度条、计数看板等「只读流」场景。

需要双向通信（如下发控制指令）时请用 [WebSocket](../websocket/WebSocket%20数据源使用手册.md)。

## 三、快速开始（演示模式，3 步上手）

演示模式**无需任何真实接口与本地端口**：模拟数据由桌面端内置模拟引擎（Rust `DemoAdapter`）直接生成锯齿波，经 Tauri IPC 推送给画面。启动桌面应用（`npx tauri dev`）后即可体验。

**第 1 步：创建数据源**

「🔌 数据源管理」→「＋ 新增数据源」：

- 名称：`内置SSE模拟源`
- 类型：`SSE`
- 地址：`http://localhost:8082/sse`（演示模式下自动预填，仅作演示标识）

**第 2 步：绑定节点**

选中节点 → 「数据绑定」标签页：

- 数据源：`内置SSE模拟源`
- 点ID：`progress.task.01`（任意字符串，作为 `pointId` 查询参数）
- 转换函数：留空

**第 3 步：观察数据**

节点显示一个 0~100 的数值，每秒上升约 10，升到 100 后归零重新斜升（锯齿波），周期约 10 秒。

## 四、配置项说明

| 字段 | 说明 | 示例 |
| --- | --- | --- |
| 名称 | 数据源显示名 | `产线进度推送` |
| 类型 | `SSE` | — |
| 地址 | SSE 接口地址（不含 pointId 参数） | `http://192.168.0.40:8082/sse` |
| 备注 | 可选 | `生产计数流` |

> 编辑器会自动追加 `?pointId=<点ID>`。SSE 基于 WebView 原生 `EventSource`，真实模式下**无需独立网关**；演示模式则由桌面端 Rust 网关内置生成数据。

## 五、点ID与接口约定

点ID作为查询参数 `pointId` 传给接口。服务端需以 `text/event-stream` 持续推送标准 SSE 帧：

```
data: {"id":"progress.task.01","value":42,"timestamp":1730000000000,"quality":"good"}

```

即每条消息以 `data: ` 开头、以两个换行结尾。编辑器解析 JSON 后取 `value`（兼容 `data`）作为数值。

## 六、实际案例：生产计数实时看板

**场景**：MES 系统提供 SSE 接口 `http://mes.local:8080/stream`，按 `?pointId=xxx` 推送各产线的实时产量计数。需要在画布上显示 2 条产线的当班产量。

**操作步骤**：

1. 数据源管理 → 新增：名称 `MES产量流`，类型 `SSE`，地址 `http://mes.local:8080/stream`。
2. 放置 2 个数字标签，绑定该数据源，点ID分别填 `line.1.count`、`line.2.count`。
3. 若要把浮点计数取整，转换函数填 `(raw) => Math.floor(raw)`。

**预期效果**：两个标签随服务端推送实时累加显示，断网恢复后浏览器自动重连继续接收。

## 七、接入自己的 SSE 接口

服务端需满足：

1. 响应头 `Content-Type: text/event-stream`、`Cache-Control: no-cache`、`Connection: keep-alive`。
2. 每条数据写成 `data: <JSON>\n\n`。
3. 可选发送 `retry: 3000\n\n` 指定浏览器重连间隔（毫秒）。
4. 跨域时返回 `Access-Control-Allow-Origin`。

## 八、常见问题

**Q：连接断了要手动重连吗？**
不需要。`EventSource` 由浏览器自动重连（间隔可由服务端 `retry` 字段控制）。

**Q：为什么收不到数据？**
检查：① 接口是否真的以 `text/event-stream` 持续输出而非一次性返回；② 每条消息是否为 `data: ...\n\n` 格式；③ 点ID是否与服务端区分推送的主题一致；④ 是否被代理/网关缓冲（部分 Nginx 配置需关闭缓冲 `proxy_buffering off`）。

**Q：能一个连接订阅多个点吗？**
浏览器 `EventSource` 本身按 URL 区分，本编辑器为每个点ID建立独立的 EventSource（各自 URL 带不同 pointId）。

## 九、注意事项

- HTTP/1.1 下浏览器对同域名并发连接有限（通常 6 个），订阅点很多时注意连接数，或考虑 WebSocket。
- SSE 仅单向，控制类需求请用 WebSocket。
- 经过 Nginx 等反向代理时，务必关闭响应缓冲，否则数据会被攒批延迟到达。
