# 西门子 S7 数据源 · 用户使用手册

> 适用版本：roc-wes 编辑器 ｜ 数据源类型标识：`s7` ｜ 演示地址：`ws://localhost:8084/s7` ｜ 真实网关：`ws://localhost:19101/s7`

## 一、简介

西门子 S7 数据源用于接入西门子 S7 系列 PLC（S7-300/400/1200/1500 等），通过 **S7comm 协议**读写 PLC 的数据块（DB）、标志位（M 区）、输入/输出（I/Q 区）等寄存器。这是工厂车间最常见的 PLC 接入方式之一。

由于 S7comm 是基于 TCP 的二进制协议，**浏览器无法直接连接 PLC**，因此编辑器通过一个独立的「WS 网关」桥接：浏览器经 WebSocket 连到网关，网关再用 S7comm 连接真实 PLC。为了便于演示，系统还内置了一个「演示网关」和一个「软件仿真 PLC」，无需真实硬件即可跑通全链路。

## 二、适用场景

- 现场使用西门子 S7 系列 PLC，需要把 PLC 寄存器数据（温度、压力、计数、阀门开度、运行状态位）实时显示到监控画面。
- 调试阶段没有真实 PLC，想用软件仿真验证画面逻辑。

其他品牌/协议的 PLC 请选用对应数据源：通用寄存器扫描可用 [Modbus](../modbus/用户使用手册.md)，统一架构设备可用 [OPC UA](../opc/用户使用手册.md)。

## 三、两种连接模式

| 模式 | 网关 | 用途 | 是否需真实 PLC |
| --- | --- | --- | --- |
| 演示模式 | 内置演示网关 `ws://localhost:8084/s7`（随 `npm run dev` 自启） | 快速体验、画面开发 | 否（生成模拟数据） |
| 真实设备 | 独立网关 `ws://localhost:19101/s7`（`npm run s7-gateway`） | 连接真实 PLC 或仿真 PLC | 是（或起仿真端） |

两种模式在编辑器里的订阅协议完全一致，区别只是数据源「地址」不同，以及真实模式需要填写 PLC 连接参数。

## 四、快速开始（演示模式，3 步上手）

**第 1 步：创建数据源**

「🔌 数据源管理」→「＋ 新增数据源」：

- 名称：`内置西门子S7模拟源`
- 类型：`西门子 S7`
- 连接模式：选「演示模式（内置模拟网关）」
- 地址：自动填充 `ws://localhost:8084/s7`

**第 2 步：绑定节点**

选中节点 → 「数据绑定」标签页：

- 数据源：`内置西门子S7模拟源`
- 点ID：`DB1,REAL0`（演示模式下任意地址都会返回模拟值）
- 转换函数：留空

**第 3 步：观察数据**

节点显示一个 0~100 的数值，模拟 PLC 设定值跟踪：每 5 秒切换一个目标值并平滑逼近（叠加微噪声），类似温度/压力的设定跟踪过程。

## 五、配置项说明

在「数据源管理」对话框中，S7 类型提供演示/真实切换。真实模式下需配置：

| 字段 | 说明 | 默认值 | 示例 |
| --- | --- | --- | --- |
| 连接模式 | 演示模式 / 真实设备 | 演示 | 真实设备 |
| 主机地址 | PLC 的 IP 或域名（真实模式必填） | — | `192.168.0.10` |
| 端口 | S7comm 端口 | `102` | `102` |
| 机架号(rack) | PLC 机架号 | `0` | `0` |
| 槽号(slot) | S7-300/400 通常为 2；S7-1200/1500 通常为 1 | `2` | `2` |
| 轮询间隔(ms) | 网关读取 PLC 的周期 | `1000` | `500` |
| 地址 | 网关 WS 地址（真实模式自动填 `ws://localhost:19101/s7`） | — | — |

> rack/slot 必须与 PLC 实际配置一致，否则连接失败。S7-1200/1500 还需在 PLC 侧「允许来自远程对象的 PUT/GET 通信」。

## 六、点ID（PLC 地址）填写规则

点ID采用 nodes7 的地址字符串格式，**这是 S7 数据源最容易出错的地方**：

| 区域 | 格式示例 | 含义 |
| --- | --- | --- |
| 数据块 DB | `DB1,REAL0` | DB1 从字节 0 开始的 REAL（浮点，4 字节） |
| 数据块 DB | `DB1,INT4` | DB1 从字节 4 开始的 INT（整型，2 字节） |
| 数据块 DB | `DB1,WORD6` | DB1 从字节 6 开始的 WORD（2 字节） |
| 数据块位 | `DB1,X0.0` | DB1 字节 0 的第 0 位 |
| 标志位 M 区 | `MB0` / `MW0` / `MD0` / `MR0` | M 区字节/字/双字/实数 |
| 标志位 | `M0.0` | M 区字节 0 的第 0 位 |
| 输入/输出 | `IB0` / `QB0` | 输入/输出字节 |

类型字母：`X`=位、`B`=字节、`W`=字、`D`=双字、`R`/`REAL`=实数、`INT`=整型、`WORD`/`DWORD` 等。

⚠️ **常见错误**：`DB1,REAL0,1` 这种带「第三段逗号」的写法是**非法**的，会被静默丢弃导致读不到数据。正确写法是 `DB1,REAL0`（数组长度用 `.` 表示，如 `DB1,REAL0.4` 表示 4 个 REAL）。

## 七、实际案例：反应釜温度与搅拌状态监控

**场景**：一台西门子 S7-1200 PLC（IP `192.168.1.50`）控制反应釜，PLC 程序里：DB10 的 REAL0 存反应釜温度（℃），DB10 的 INT4 存搅拌转速（rpm），M0.0 是加热阀开关。需要在画布上显示温度、转速，并用一个指示灯显示加热阀状态。

**操作步骤**：

1. 数据源管理 → 新增：
   - 名称：`反应釜PLC`
   - 类型：`西门子 S7`
   - 连接模式：真实设备
   - 主机地址：`192.168.1.50`，端口 `102`，机架 `0`，槽号 `1`（S7-1200）
   - 地址自动为 `ws://localhost:19101/s7`
2. 启动网关：在项目目录运行 `npm run s7-gateway`。
3. 画布放置 2 个数字标签 + 1 个指示灯节点，绑定该数据源，点ID分别填：
   - 温度：`DB10,REAL0`，转换函数 `(raw) => Math.round(raw * 10) / 10`
   - 转速：`DB10,INT4`
   - 加热阀：`M0.0`，转换函数 `(raw) => raw ? '开启' : '关闭'`

**预期效果**：温度、转速按轮询间隔实时刷新；加热阀指示灯随 M0.0 通断切换。

## 八、连接真实设备 / 软件仿真

**连接真实 PLC**：

1. 确认 PLC 已上电、网络可达（`ping 192.168.1.50`），S7comm 端口 102 开放。
2. S7-1200/1500 需在博途中勾选「允许 PUT/GET 通信」并下载。
3. `npm run s7-gateway` 启动网关，数据源用真实模式并填好 host/rack/slot。

**用软件仿真 PLC 验证（无需硬件）**：

系统自带一个纯 JS 实现的 S7comm 仿真 PLC（`gateway/s7-simulator.ts`）：

```bash
npm run s7-simulator    # 启动仿真 PLC，监听 19503
npm run s7-gateway      # 启动网关，监听 19101
```

数据源真实模式配置：主机地址 `127.0.0.1`，端口 `19503`，机架 `0`，槽号 `2`。仿真端会按请求的字节长度返回模拟值（1 字节→BYTE、2 字节→INT、4 字节→REAL），可用 `DB1,REAL0`、`DB1,INT4`、`MB0` 等地址订阅验证。

## 九、常见问题

**Q：网关报「设备未连接」/ 连不上 PLC？**
检查：① host/port/rack/slot 是否与 PLC 一致（S7-1200/1500 槽号常为 1）；② PLC 是否允许 PUT/GET；③ 防火墙是否放行 102 端口；④ 网关控制台的具体错误信息。

**Q：订阅了某个地址但一直没数据（quality=bad）？**
多半是地址格式非法被丢弃（如多了第三段逗号 `DB1,REAL0,1`），或该地址超出 PLC 实际 DB 长度。核对地址格式与 DB 实际定义。

**Q：演示模式和真实模式数据不一样？**
演示模式由内置网关生成「设定值跟踪」模拟数据，忽略设备参数；真实模式由独立网关连接真实 PLC/仿真端读取。二者仅用于不同阶段，订阅协议一致。

## 十、注意事项

- 轮询间隔最小 200ms；过短会增加 PLC 通信负载，建议按实际需要设置（一般 500~2000ms）。
- rack/slot 填错是最常见的连接失败原因，务必对照 PLC 硬件配置。
- 生产环境网关与 PLC 之间建议处于同一受控网段，注意工业网络安全。
