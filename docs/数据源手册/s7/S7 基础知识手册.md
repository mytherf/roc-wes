# S7 基础知识手册

> 本篇为通用协议知识科普。roc-wes 桌面版的 S7 客户端由 Rust 网关（`snap7-client`，纯 Rust 实现）实现；项目内的接入方式见 [S7 数据源使用手册](./S7%20数据源使用手册.md) 与 [开发手册](./S7%20数据源开发手册.md)。

## 一、什么是 S7comm？

S7comm（S7 Communication）是西门子私有的一种工业通信协议，运行在 ISO-on-TCP（RFC 1006）之上，用于上位机（HMI/SCADA/工程软件）与西门子 S7 系列 PLC（S7-300/400/1200/1500 等）之间的数据读写。它随 STEP 7 生态在 1990 年代随 S7-300/400 一起普及，至今仍是工厂车间访问西门子 PLC 最主流的方式。

### 核心特性

- **TCP 传输**：默认使用 TCP **102** 端口，底层依次封装 TPKT → COTP → S7 协议层。
- **主从模式**：PLC 被动应答，上位机主动发起读/写请求；PLC 不会主动推送数据（与 WebSocket/MQTT 的推送模型相反）。
- **二进制编解码**：报文为紧凑二进制结构，数值一律**大端序**（Big-Endian）。
- **按地址寻址**：直接读写 PLC 的数据块（DB）、标志位（M 区）、输入/输出（I/Q 区），无需中间映射表。
- **批量读取**：一条请求可携带多个读项（Multi-Var Read），受 PDU 大小约束自动分批。

### 协议家族演进

| 协议 | 适用机型 | 说明 |
|------|---------|------|
| **S7comm** | S7-300/400，及开启 PUT/GET 的 1200/1500 | 经典协议，生态工具支持最广 |
| **S7comm Plus** | S7-1200/1500 | 新一代协议，带会话认证（integrity mode），可直接访问优化 DB 块；TIA Portal 在线诊断即使用此协议 |


## 二、为什么需要了解 S7comm？

在工业现场读取西门子 PLC 的数据，常见路径有三条：

| 方案 | 工作原理 | 优缺点 |
|------|---------|--------|
| **OPC UA 服务器** | PLC 或网关暴露标准化 OPC UA 服务 | 标准化、跨厂商，但需 PLC 固件支持或额外网关，配置偏重 |
| **Modbus TCP** | PLC 加装 CP 模块或网关转换为 Modbus | 通用性好，但需要额外硬件/配置，地址映射不直观 |
| **S7comm 直连** | 上位机直接用 S7 协议读 PLC | 零额外设备、按 PLC 原生地址读写、延迟低；但仅限西门子设备 |

对于"监控西门子 PLC 寄存器级数据"这一典型需求，S7comm 直连是**成本最低、地址最直观**的方式，也是 roc-wes 桌面版 S7 数据源采用的方案。


## 三、S7comm 的工作原理

### 1. 协议栈与建连过程

S7comm 的连接建立需要三层握手，缺一不可：

```
┌─────────────┐
│  S7 协议层   │  ③ S7 Setup Communication（协商 PDU 大小）
├─────────────┤
│    COTP     │  ② COTP Connect Request/Confirm（携带 rack/slot 寻址）
├─────────────┤
│ TPKT(RFC1006)│  ① TCP 连接建立（默认端口 102）
├─────────────┤
│     TCP     │
└─────────────┘
```

- **TPKT**：RFC 1006 定义的 4 字节头（版本+长度），为上层协议分帧。
- **COTP**（ISO 8073 子集）：面向连接传输层，连接请求中携带 **rack/slot** 参数定位 PLC 的 CPU；数据阶段帧头仅 3 字节（PDU 类型 `0xF0`）。
- **S7 层**：`Setup Communication` 请求协商 **PDU 大小**（通常 240~960 字节，1200/1500 可达 960+）与最大并发作业数（AMQ），协商结果决定单次批量读能放多少项。

连接建立后，读写以「作业（Job）→ 应答（Ack_Data）」一问一答进行。

### 2. S7 报文结构

一次读请求的报文骨架：

| 层 | 字段 | 说明 |
|------|------|------|
| TPKT | 版本 / 长度 | 固定 4 字节 |
| COTP | PDU 类型 | 数据帧为 `0xF0`，含 TPDU 编号 |
| S7 头 | 协议 ID / ROSCTR | ROSCTR：1=Job（请求）3=Ack_Data（应答） |
| S7 头 | 参数偏移 / 数据偏移 | 定位后续两段 |
| S7 参数 | 功能码 | `0x04`=Read Var、`0x05`=Write Var、`0xF0`=Setup |
| S7 参数 | 读项列表 | 每项：数据区 + DB 号 + 起始字节 + 长度 |
| S7 数据 | 返回值 + 字节串 | 每段带传输大小与长度前缀（写入时为待写数据） |

应答中每个读项各有独立的**返回码**（`0xFF`=成功，`0x0A`=对象不存在等），因此批量读中单点失败不影响其他点的结果解析。

### 3. 数据区与寻址

S7 PLC 的存储按「数据区 + 字节偏移 + 位」寻址：

| 数据区 | 缩写 | 说明 |
|------|------|------|
| 数据块 | DB | 用户程序定义的变量区，最常用（如 `DB1`） |
| 标志位区 | M（Merker） | 全局中间变量，按字节/位访问 |
| 过程输入 | I | 数字量/模拟量输入映像 |
| 过程输出 | Q | 数字量/模拟量输出映像 |

常用数据类型与字节宽度：

| 类型 | 宽度 | 说明 |
|------|------|------|
| BOOL | 1 位 | 以 `字节.位` 寻址（如 `M0.0`） |
| BYTE | 1 字节 | 无符号 0~255 |
| INT / WORD | 2 字节 | 有符号 / 无符号 |
| DINT / DWORD | 4 字节 | 有符号 / 无符号 |
| REAL | 4 字节 | IEEE 754 单精度浮点 |
| LREAL | 8 字节 | IEEE 754 双精度浮点（仅部分机型/场景） |

所有多字节数值在 S7 报文中均为**大端序**，上位机解码时需注意字节序转换。

### 4. PDU 与批量读

- **PDU**（Protocol Data Unit）是 S7 层单个报文的最大负载，由建连时协商确定。
- 一次 Read Var 请求能容纳的读项数量受 PDU 限制（每个读项参数约 12 字节 + 应答数据开销），客户端库通常**自动分批**。
- 批量读（Multi-Var Read）相比逐点读可大幅减少往返次数，是高频轮询场景的关键优化。

### 5. rack/slot 寻址

COTP 连接请求通过 rack/slot 定位目标 CPU，填错会直接导致连接失败：

| 机型 | 典型 rack | 典型 slot | 备注 |
|------|-----------|-----------|------|
| S7-300 / S7-400 | 0 | 2 | CPU 默认插在 2 号槽 |
| S7-1200 / S7-1500 | 0 | 1 | 且需开启 PUT/GET（见下） |

### 6. S7-1200/1500 的访问限制

- 需在 TIA Portal 中为 CPU 开启 **PUT/GET 通信访问**；
- 「**优化的块访问**」（Optimized block access）DB 块无法被传统 S7comm 按偏移读取——要么关闭该 DB 的优化访问，要么改用 S7comm Plus；这是**协议层限制**，与客户端库无关。


## 四、客户端使用（示例）

### 1. Python（python-snap7）

```python
import snap7
from snap7.util import get_real, get_bool

plc = snap7.client.Client()
# 连接：IP、rack、slot
plc.connect('192.168.0.10', 0, 2)

# 读 DB1 起始偏移 0 的 4 字节并按 REAL 解码
data = plc.db_read(1, 0, 4)
value = get_real(data, 0)
print('DB1.REAL0 =', value)

# 读标志位 M0.0
m = plc.mb_read(0, 1)
print('M0.0 =', get_bool(m, 0, 0))

plc.disconnect()
```

### 2. Rust（snap7-client，roc-wes 采用）

```rust
use snap7_client::{ConnectParams, MultiReadItem, S7Client};
use snap7_client::transport::TcpTransport;

let params = ConnectParams { rack: 0, slot: 2, ..Default::default() };
let client = S7Client::<TcpTransport>::connect("192.168.0.10:102", params).await?;

// 单点读：DB1 偏移 0 读 4 字节
let bytes = client.db_read(1, 0, 4).await?;
let value = f32::from_be_bytes(bytes[..4].try_into().unwrap());

// 批量读：一次携带多个读项（库内自动 PDU 分批）
let items = vec![MultiReadItem::db(1, 0, 4), MultiReadItem::db(1, 4, 4)];
let results = client.read_multi_vars(&items).await?;
```

## 五、模拟与无真机联调

没有真实 PLC 时，可用模拟器完成协议层联调：

- **snap7-server**：Snap7 生态自带的服务端组件，可作为进程内/独立进程的虚拟 PLC，响应真实的 TPKT/COTP/S7 帧；roc-wes 的 Rust 集成测试即用它跑往返测试（`cargo test -p gateway-s7`）。
- **PLCSIM / PLCSIM Advanced**：西门子官方仿真软件，PLCSIM Advanced 支持通过 TCP/IP 被外部连接（S7-1500 镜像）。
- **HslCommunicationTools**：国产工业联调工具，内置 S7 服务器模拟页签，可手工收发 S7 帧。


## 六、应用场景

S7comm 适用于需要直接读写西门子 PLC 寄存器级数据的场景：

| 场景 | 说明 |
|------|------|
| **SCADA 监控画面** | 实时显示产线设备状态、温度/速度等遥测量 |
| **WCS 仓储调度** | 读取堆垛机/输送线 PLC 的位置与运行状态 |
| **设备 OEE 采集** | 按周期采集运行/停机位，统计稼动率 |
| **MES 数据上云** | 网关按轮询把 PLC 数据归集到数据库/消息队列 |
| **报警联动** | 监视关键位（故障字/急停位）触发告警 |


## 七、S7comm vs Modbus TCP vs OPC UA

| 对比维度 | S7comm | Modbus TCP | OPC UA |
|----------|--------|-----------|--------|
| 设备范围 | 仅西门子 S7 | 多厂商（含网关转换） | 多厂商标准化 |
| 寻址方式 | DB/M/I/Q 原生地址 | 寄存器/线圈编号（需映射） | NodeId（信息模型） |
| 传输层 | TCP 102（ISO-on-TCP） | TCP 502 | TCP 4840（opc.tcp） |
| 数据模型 | 字节级、无元数据 | 字节级、无元数据 | 带类型、描述与安全策略 |
| 推送能力 | 无（轮询读） | 无（轮询读） | 支持订阅（Publish） |
| 配置成本 | 低（仅需 rack/slot） | 中（需映射表） | 高（服务器/证书/权限） |
| 典型选择 | 西门子设备直读 | 仪表/第三方 PLC | 跨厂商统一接入 |


## 八、最佳实践与注意事项

### 安全性

1. **S7comm 无认证、无加密**：任何能连通 TCP 102 的主机都可读写 PLC，务必将 PLC 置于**隔离工业网络**（VLAN/防火墙），勿暴露公网。
2. **读写权限分离**：监控类系统只做读操作；写操作应走受控通道并留审计日志。
3. **生产环境限制上位机数量**：PLC 的 S7 连接资源有限（S7-300 通常 10 个左右），避免无节制建连。

### 稳定性

1. **断线重连**：工业网络不稳定，客户端必须实现自动重连（建议指数退避，如 2s→30s），重连后恢复轮询。
2. **超时与心跳**：为每次读设置超时；长时间空闲的连接可能被中间设备断开，可周期性发读请求保活。
3. **单点故障隔离**：批量读失败时降级逐点读，避免一个坏点拖垮整轮采集。

### 性能

1. **批量读优先**：尽量用 Multi-Var Read 合并点位，减少 TCP 往返；点很多时注意 PDU 分批。
2. **合理轮询间隔**：PLC 通信资源（PDU/连接数）有限，测点多时放宽间隔（如下限 200ms 起步按负载调）。
3. **按需读取**：只订阅画面真正需要的点位，避免全 DB 大范围盲读。

### 注意事项

- **字节序**：S7 数值一律大端序，与 x86 小端相反，解码必须转换。
- **优化 DB 块**：S7-1200/1500 优化访问的 DB 无法被传统 S7comm 读取，需 PUT/GET + 关闭优化，或改用 S7comm Plus。
- **地址语法因库而异**：`DB1,REAL0`（nodes7 风格）、`DB1.DBW0`（S7.Net 风格）、`%DB1.DBW0`（PLC4X 风格）互不通用，集成前先确认所用库的语法（roc-wes 采用 nodes7 风格）。
- **浮点对齐**：REAL 按 4 字节边界存放，偏移写错 1 字节会得到完全错误的数值。
