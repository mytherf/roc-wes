# 西门子 S7 数据源 · 开发手册

> 面向维护、调试或扩展 S7 数据接入的开发者。数据源类型标识：`s7` ｜ 桌面版真实模式：✅ 已上线（`gateway-s7`，snap7-client 0.1.7）

## 一、现状与架构

配置 → IPC → 工厂 → 适配器全链路已打通，真实模式可用：

```
前端：
  DataSourceDeviceConfig（host/port/rack/slot/pollInterval）
      ──▶ deviceConfig.ts buildDeviceConfig('s7') → { kind:'s7', host, port, rack, slot, pollIntervalMs }
      ──▶ IpcGatewayService ──IPC──▶ gateway_connect

Rust：
  gateway-core/src/config.rs  S7Config { host, port:102, rack:0, slot:2, poll_interval_ms:1000 }
  factory.rs  DeviceConfig::S7(cfg) → Box::new(gateway_s7::S7Adapter::new(cfg))
  crates/gateway-s7  实现 trait DeviceAdapter（connect/read/disconnect/kind）
```

演示模式同样可用：`config.demo === true`（地址可为空）时映射 `{ kind:'demo', profile? }`，由 `gateway-demo` 生成模拟曲线（默认正弦，可在数据源对话框「演示波形」中更换；点 ID 原样接受）。

前端 WS 网关桥接实现（原 `S7Service`）已随纯桌面化改造移除（可从 git 历史找回）；内置 Node 网关（`gateway/s7-gateway.ts`，19101）、仿真 PLC（`gateway/s7-simulator.ts`，19503）与 mock 桥接（8084）也已退役。

## 二、点 ID 约定（已实现合同）

沿用 nodes7 风格地址字符串，与旧实现保持一致：

| 数据区 | 语法 | 示例 | 状态 |
| --- | --- | --- | --- |
| DB 标量 | `DB{n},{类型}{偏移}` | `DB1,REAL0` / `DB1,INT4` / `DB1,WORD6` | ✅ |
| DB 位 | `DB{n},X{字节}.{位}`（X 可省略） | `DB1,X0.0` / `DB1,332.0` | ✅ |
| DB 数组 | `DB{n},{类型}{偏移}.{长度}` | `DB1,REAL0.4` | ⏳ v2 规划（当前返回 InvalidPoint） |
| M 区 | `MB/MW/MD{偏移}`、位 `M{字节}.{位}` | `MB0` / `M10.3` | ✅ |
| I / Q 区 | `IB/IW/ID{n}` / `QB/QW/QD{n}` | `IB0` / `QW2` | ✅ |

类型关键字：REAL(f32) / LREAL(f64) / INT(i16) / WORD(u16) / DINT(i32) / DWORD(u32) / BYTE 或 B(u8)，大小写不敏感；数值一律大端序解码。非法格式（含旧文档中的 `MR` 实数区写法）返回 `InvalidPoint`，单点跳过不影响其他点。

## 三、选型结论与实现

候选对比后选定 **`snap7-client = "=0.1.7"`**（rs-snap7，MIT，纯 Rust）：

| 候选 | 结论 |
| --- | --- |
| snap7-client | ✅ 纯 Rust 原生 tokio 异步、S7Comm + S7CommPlus、多读自动 PDU 分批、自带进程内模拟器（snap7-server）可做无真机集成测试 |
| tokio-s7 | ❌ 零测试零 CI |
| turbos7 | ❌ 仓库已 404 |
| s7 | ❌ 许可证不明 |
| snap7-rs / rust-snap7 | ❌ C FFI，与纯 Rust 打包策略冲突 |

精确 pin `=0.1.7`（pre-1.0，防 API 漂移）。实现要点：

- `connect`：host:port 域名解析后按 rack/slot 构造 `ConnectParams`（连接超时 5s）建立 S7Client；失败返回 `Connect`。
- `read`：点位构造 `MultiReadItem` 一次批量读（库内自动 PDU 分批）；批量失败降级逐点读以隔离单点故障，首点失败视为连接级故障抛出以触发引擎重连。
- v1 仅 S7Comm（`S7Client`）；S7CommPlus（`S7PlusClient`，面向 1200/1500 优化 DB 块）作为后续配置项演进。
- 测试：5 个点位解析/解码单测 + 4 个集成测试（snap7-server 进程内模拟器跑真实 TPKT/COTP/S7 帧往返；另覆盖死端口连接失败、未连接读取）。

## 五、S7Config 参考

```rust
pub struct S7Config {
    pub host: String,
    pub port: u16,             // 默认 102
    pub rack: u8,              // 默认 0
    pub slot: u8,              // 默认 2（与数据源对话框一致；S7-1200/1500 场景可配 1）
    pub poll_interval_ms: u64, // 默认 1000，引擎下限 200
}
```

前端映射见 `src/platform/deviceConfig.ts`（slot 默认 2，历史版本曾为 1，已统一）。
