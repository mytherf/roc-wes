# 西门子 S7 数据源 · 开发手册

> 面向维护、调试或扩展 S7 数据接入的开发者。数据源类型标识：`s7` ｜ 桌面版真实模式：⏳ 适配器待实现（factory 返回 `Unsupported`）

## 一、现状与架构预留

桌面版已为 S7 打通「配置 → IPC → 工厂」的全部管道，仅缺适配器实现：

```
前端已就绪：
  DataSourceDeviceConfig（host/port/rack/slot/pollInterval）
      ──▶ deviceConfig.ts buildDeviceConfig('s7') → { kind:'s7', host, port, rack, slot, pollIntervalMs }
      ──▶ IpcGatewayService ──IPC──▶ gateway_connect

Rust 已就绪：
  gateway-core/src/config.rs  S7Config { host, port:102, rack:0, slot:2, poll_interval_ms:1000 }
  factory.rs  DeviceConfig::S7(_) → Err(Unsupported("S7 适配器待 spike（snap7 绑定 / 自研 S7comm）"))

缺口：
  crates/gateway-s7（实现 trait DeviceAdapter）
```

演示模式已可用：`config` 判定为 demo 时映射 `{ kind:'demo' }`，由 `gateway-demo` 生成模拟曲线（点 ID 原样接受）。

浏览器版的 `S7Service`（WS 网关桥接实现）保留在 `src/services/`，仅供自备外部网关场景；内置 Node 网关（`gateway/s7-gateway.ts`，19101）、仿真 PLC（`gateway/s7-simulator.ts`，19503）与 mock 桥接（8084）已随清理退役（可从 git 历史找回）。

## 二、点 ID 约定（规划合同）

桌面适配器将沿用 nodes7 风格地址字符串，与旧实现保持一致，切换时无需迁移绑定：

| 数据区 | 语法 | 示例 |
| --- | --- | --- |
| DB | `DB{n},{类型}{偏移}` | `DB1,REAL0` / `DB1,INT4` / `DB1,WORD6` |
| DB 位 | `DB{n},X{字节}.{位}` | `DB1,X0.0` |
| DB 数组 | `DB{n},{类型}{偏移}.{长度}` | `DB1,REAL0.4`（长度用 `.`，三逗号非法） |
| M 区 | `MB/MW/MD/MR{偏移}`、位 `M{字节}.{位}` | `MB0` / `M0.0` |
| I / Q 区 | `IB{n}` / `QB{n}` | `IB0` / `QB0` |

## 三、S7 spike：两条技术路线

| 路线 | 方案 | 优点 | 风险 |
| --- | --- | --- | --- |
| A. snap7 绑定 | C++ 库 snap7 经 FFI 绑定（bindgen / 现成 crate） | 协议成熟、全机型覆盖、久经现场 | 原生编译与跨平台打包复杂度、许可证审查（LGPL）、静态链接体积 |
| B. 自研 S7comm | Rust 手写 TPKT/COTP/S7 PDU | 纯 Rust、无原生依赖、协议栈已有 JS 逆向经验可移植 | 开发工作量、机型兼容性需逐步验证 |

已有资产（可移植）：浏览器时代曾用纯 JS 手写 S7comm 仿真 PLC（TPKT 封帧、COTP Connect/Data、S7 Read 请求/响应、PDU ref 回显匹配），实现位于 git 历史的 `gateway/s7-simulator.ts`，其字节格式笔记对路线 B 是直接可用的参考。

验收标准建议：对 S7-300（rack 0 / slot 2）与 S7-1200/1500（slot 1、PUT/GET）各跑通 DB/M 区读取与位读取，纳入 `gateway-engine` 集成测试同构的测试集。

## 四、落地步骤（对照 Modbus 样板）

1. `crates/gateway-s7`：`S7Adapter` 实现 `trait DeviceAdapter`——`connect` 完成 TCP + COTP 连接建立，`read` 解析点 ID 并批量读（同一 DB 的多点尽量合并 PDU），`kind()` 返回 `"s7"`；
2. `Cargo.toml` 工作区根注册依赖，`src-tauri/Cargo.toml` 添加 `gateway-s7`；
3. `factory.rs`：把 `DeviceConfig::S7` 分支替换为 `Box::new(gateway_s7::S7Adapter::new(cfg))`（引擎、命令层、前端零改动）；
4. 测试：点 ID 解析单测 + 会话集成测试（可先以内存 fake PLC 验证帧交互）；
5. 更新本文档状态为已上线，并同步 [用户使用手册](./用户使用手册.md) 的现状表与总索引。

## 五、S7Config 参考

```rust
pub struct S7Config {
    pub host: String,
    pub port: u16,             // 默认 102
    pub rack: u8,              // 默认 0
    pub slot: u8,              // 默认 2（与数据源对话框一致；S7-1200/1500 场景可配 1）
    pub poll_interval_ms: u64, // 默认 1000，引擎下限 200
}
```

前端映射见 `src/platform/deviceConfig.ts`（slot 默认 2，历史版本曾为 1，已统一）。
