# OPC UA 数据源 · 用户使用手册

> 适用版本：roc-wes 编辑器 ｜ 数据源类型标识：`opc` ｜ 演示地址：`ws://localhost:8085/opc` ｜ 真实网关：`ws://localhost:19102/opc`

## 一、简介

OPC UA（OPC Unified Architecture）是工业互联的「通用语言」，一套跨平台、跨厂商的标准数据访问规范。它把设备数据抽象为带类型、带质量戳、带时间戳的「节点（Node）」，并支持复杂的安全机制与信息建模。越来越多的 PLC、SCADA、MES 都提供 OPC UA 服务器接口，是新建智能工厂的主流选择。

OPC UA 默认走 `opc.tcp://` 二进制协议，**浏览器无法直接连接**，因此编辑器通过独立 WS 网关桥接：浏览器经 WebSocket 连网关，网关再用 node-opcua 客户端连接 OPC UA 服务器。系统同样内置了「演示网关」和「软件仿真 OPC UA 服务器」，无需真实设备即可体验。

## 二、适用场景

- 现场设备/系统提供 OPC UA 服务器（如西门子 S7-1200/1500 内置 OPC UA、KEPServerEX、各类 OPC UA 网关）。
- 需要统一接入多厂商设备，或需要带质量戳/时间戳的标准化数据。
- 希望面向未来扩展（OPC UA 支持报警、事件、历史、信息建模）。

若只接西门子 PLC 且追求简单，可用 [S7](../s7/用户使用手册.md)；通用寄存器扫描可用 [Modbus](../modbus/用户使用手册.md)。

## 三、两种连接模式

| 模式 | 网关 | 用途 | 是否需真实服务器 |
| --- | --- | --- | --- |
| 演示模式 | 内置演示网关 `ws://localhost:8085/opc`（随 `npm run dev` 自启） | 快速体验、画面开发 | 否（生成模拟数据） |
| 真实设备 | 独立网关 `ws://localhost:19102/opc`（`npm run opc-gateway`） | 连接真实 OPC UA 服务器或仿真服务器 | 是（或起仿真端） |

两种模式订阅协议一致，区别仅在数据源「地址」与真实模式需填端点 URL。

## 四、快速开始（演示模式，3 步上手）

**第 1 步：创建数据源**

「🔌 数据源管理」→「＋ 新增数据源」：

- 名称：`内置OPC UA模拟源`
- 类型：`OPC UA`
- 连接模式：演示模式
- 地址：自动填充 `ws://localhost:8085/opc`

**第 2 步：绑定节点**

选中节点 → 「数据绑定」标签页：

- 数据源：`内置OPC UA模拟源`
- 点ID：`ns=2;s=Ramp`（演示模式下任意 NodeId 都会返回模拟值）
- 转换函数：留空

**第 3 步：观察数据**

节点显示一个 0~100 的量化阶梯值：每 4 秒跳变到「5 的整数倍」档位，窗口内保持不变，模拟数字化采集节点的离散读数。

## 五、配置项说明

真实模式下需配置：

| 字段 | 说明 | 默认值 | 示例 |
| --- | --- | --- | --- |
| 连接模式 | 演示模式 / 真实设备 | 演示 | 真实设备 |
| 端点 URL | OPC UA 服务器端点（真实模式必填） | — | `opc.tcp://192.168.0.20:4840` |
| 轮询间隔(ms) | 网关读取节点的周期 | `1000` | `500` |
| 地址 | 网关 WS 地址（真实模式自动填 `ws://localhost:19102/opc`） | — | — |

> 端点 URL 格式为 `opc.tcp://<主机>:<端口>`，常见端口 4840。也可只填 host/port 由网关拼出（默认端口 4840）。当前网关使用 **SecurityPolicy None + 匿名访问**，适合本地/内网仿真；生产请按需扩展证书与签名。

## 六、点ID（NodeId）填写规则

点ID是 OPC UA 节点的 **NodeId 字符串**，常见两种：

| 类型 | 格式 | 示例 |
| --- | --- | --- |
| 字符串标识 | `ns=<命名空间索引>;s=<字符串>` | `ns=2;s=Temperature` |
| 数值标识 | `ns=<命名空间索引>;i=<整数>` | `ns=2;i=1001` |

其中 `ns` 是命名空间索引（0 为 OPC UA 标准命名空间，服务器自定义命名空间通常从 2 开始）。NodeId 必须与服务器中节点的实际标识完全一致——可用 UaExpert 等 OPC UA 客户端工具浏览服务器节点树获取准确 NodeId。

## 七、实际案例：储罐液位与进料阀监控

**场景**：一台 OPC UA 服务器（端点 `opc.tcp://192.168.1.100:4840`）暴露储罐数据，命名空间索引 2 下：`s=Tank.Level`（液位，Double，0~100%）、`s=Tank.Temp`（温度，Double）、`s=Valve.Feed`（进料阀开闭，Boolean）。需要在画布上显示液位、温度，并用指示灯显示进料阀状态。

**操作步骤**：

1. 数据源管理 → 新增：
   - 名称：`储罐OPC服务器`
   - 类型：`OPC UA`
   - 连接模式：真实设备
   - 端点 URL：`opc.tcp://192.168.1.100:4840`
   - 地址自动为 `ws://localhost:19102/opc`
2. 启动网关：`npm run opc-gateway`。
3. 画布放置 2 个数字标签 + 1 个指示灯，绑定该数据源，点ID分别填：
   - 液位：`ns=2;s=Tank.Level`，转换函数 `(raw) => raw.toFixed(1)`
   - 温度：`ns=2;s=Tank.Temp`
   - 进料阀：`ns=2;s=Valve.Feed`，转换函数 `(raw) => raw ? '开启' : '关闭'`

**预期效果**：液位、温度按轮询间隔刷新；进料阀指示灯随布尔值切换。

## 八、连接真实设备 / 软件仿真

**连接真实 OPC UA 服务器**：

1. 确认服务器端点可达（如用 UaExpert 先连上验证）。
2. 确认匿名访问已启用，或按生产要求配置安全策略（当前网关为 None/匿名）。
3. `npm run opc-gateway` 启动网关，数据源真实模式填端点 URL。

**用软件仿真服务器验证（无需硬件）**：

系统自带 node-opcua 仿真服务器（`gateway/opc-simulator.ts`），暴露 5 个节点：

```bash
npm run opc-simulator   # 启动仿真服务器 opc.tcp://127.0.0.1:19504/UA/Simulator
npm run opc-gateway     # 启动网关 19102
```

| NodeId | 含义 | 数据类型 | 数据特征 |
| --- | --- | --- | --- |
| `ns=2;s=Ramp` | 斜坡 | Double | 0~100 锯齿波（10s 周期） |
| `ns=2;s=Sine` | 正弦 | Double | 0~100 正弦 |
| `ns=2;s=Triangle` | 三角波 | Double | 100~900（12s 周期） |
| `ns=2;s=Counter` | 计数器 | Int32 | 每秒 +1 |
| `ns=2;s=Status` | 开关 | Boolean | 每 3s 翻转 |

数据源真实模式端点 URL 填 `opc.tcp://127.0.0.1:19504`，即可订阅上述节点验证全链路。

## 九、常见问题

**Q：网关报连接失败 / 节点状态异常？**
检查：① 端点 URL 是否正确（`opc.tcp://` 前缀、端口）；② 服务器是否允许匿名/None 安全策略；③ NodeId 是否与服务器一致（命名空间索引尤其容易错）；④ 网关控制台错误信息。

**Q：怎么知道服务器里有哪些节点和 NodeId？**
用 UaExpert、Prosys OPC UA Client 等工具连接服务器浏览节点树，复制节点的 NodeId 填入点ID。

**Q：演示模式和真实模式数据不一样？**
演示模式由内置网关生成「量化阶梯」模拟数据，忽略设备参数；真实模式由独立网关连接真实/仿真服务器读取。订阅协议一致。

## 十、注意事项

- 当前网关安全策略为 None + 匿名，**仅适合本地仿真与受控内网**；公网或生产环境务必启用签名加密与用户鉴权。
- 轮询间隔最小 200ms；OPC UA 也支持订阅（Subscription）推送模式，如需更低延迟可由开发侧扩展（见开发手册）。
- NodeId 命名空间索引（ns）填错会读到 BadNodeIdUnknown，务必核对。
