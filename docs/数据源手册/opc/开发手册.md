# OPC UA 数据源 · 开发手册

> 面向维护、调试或扩展 OPC UA 数据接入的开发者。数据源类型标识：`opc` ｜ 桌面版真实模式：✅ 已上线（`gateway-opcua`，opcua crate 0.12）

## 一、现状与架构

配置 → IPC → 工厂 → 适配器全链路已打通，真实模式可用：

```
前端：
  OpcProtocolConfig（地址栏 url：端点 URL + 轮询间隔，注册表驱动）
      ──▶ deviceConfig.ts buildDeviceConfig('opc') → { protocol:'opc', endpoint, pollIntervalMs }
      ──▶ IpcGatewayService ──IPC──▶ gateway_connect

Rust：
  gateway-core/src/config.rs  OpcConfig { endpoint, poll_interval_ms:1000 }
  factory.rs  DeviceConfig::Opc(cfg) → Box::new(gateway_opcua::OpcuaAdapter::new(cfg))
  crates/gateway-opcua  实现 trait DeviceAdapter（connect/read/disconnect/kind）
```

演示模式同样可用：`config.demo === true`（地址可为空）时映射 `{ protocol:'opc', isMock:true, profile? }`（演示模式不是独立协议），由 `gateway-demo` 生成模拟曲线（默认正弦，可在数据源对话框「演示波形」中更换；NodeId 原样接受，不做格式校验）。

前端 WS 网关桥接实现（原 `OpcService`）已随纯桌面化改造移除（可从 git 历史找回）；内置 Node 网关（`gateway/opc-gateway.ts`，19102）、仿真服务器（`gateway/opc-simulator.ts`，19504）与 mock 桥接（8085）也已退役。

## 二、点 ID 约定（已实现合同）

点 ID 为 OPC UA NodeId 字符串：

| 形式 | 示例 | 状态 |
| --- | --- | --- |
| 字符串标识 `ns={n};s={str}` | `ns=2;s=Ramp` | ✅ |
| 数字标识 `ns={n};i={num}` | `ns=2;i=1001` | ✅ |
| GUID `g=` / ByteString `b=` | — | ⏳ 后续演进 |

合同要求显式 `ns=` 段；解析失败返回 `InvalidPoint`，单点跳过不影响其他点（与 Modbus/S7 适配器行为一致）。

## 三、技术方案与实现

采用 Rust **`opcua` crate（locka99/opcua，0.12.0，MPL-2.0）**，features `client`：

| 项 | 方案 |
| --- | --- |
| 读取模型 | 轮询 `Read` 服务（与引擎轮询模型天然对齐）；每轮点位一次批量 Read |
| 安全策略 | 匿名认证 + SecurityPolicy None（与旧 Node 实现行为对齐）；证书/加密作为后续配置项 |
| 会话管理 | `ClientBuilder` 构造客户端 → `connect_to_endpoint` 建立会话；`session_retry_limit(0)`，重连完全交给网关引擎 |
| 质量映射 | `DataValue`：value → JSON（Variant 逐类型转换）、sourceTimestamp → timestamp（缺失回退本地时间）、statusCode → quality（Good→good / Bad→bad / Uncertain→uncertain）；Bad 点跳过 |
| 演进方向 | `Subscription + MonitoredItem` 事件驱动推送（需引擎支持「适配器主动推送」语义） |

实现要点：

- opcua 0.12 客户端为**同步阻塞 API**（内部自带独立 tokio runtime），所有阻塞调用（connect/read/disconnect）均经 `tokio::task::spawn_blocking` 执行，不阻塞引擎运行时线程。
- Variant 支持：Boolean / 各宽度整数 / Float / Double / String / DateTime / LocalizedText；非有限浮点（NaN/Inf）与数组、ByteString 等 v1 不支持的类型跳过该点并告警。
- 测试：5 个 NodeId 解析/值映射单测 + 2 个集成测试（死端口连接失败、未连接读取）。

### 构建依赖：OpenSSL（Windows MSVC）

opcua 硬依赖 OpenSSL。本机需安装预编译 OpenSSL（`winget install ShiningLight.OpenSSL.Dev`，默认 `C:\Program Files\OpenSSL-Win64`），链接参数已固化在仓库根 `.cargo/config.toml`（静态链接 `libssl_static/libcrypto_static`，发布包无需携带 OpenSSL DLL）。

## 五、OpcConfig 参考

```rust
pub struct OpcConfig {
    pub endpoint: String,      // 如 opc.tcp://127.0.0.1:4840
    pub poll_interval_ms: u64, // 默认 1000，引擎下限 200
}
```

前端映射见 `src/platform/deviceConfig.ts`：端点地址与其他协议一致，统一填在数据源 `url` 字段（如 `opc.tcp://192.168.0.30:4840`），兼容旧数据源回退 `config.endpoint`，兜底 `opc.tcp://127.0.0.1:4840`。
