# WebSocket 数据源 · 用户使用手册

> 适用版本：roc-wes 编辑器（桌面版） ｜ 数据源类型标识：`websocket` ｜ 演示模式：无需填写地址（数据由内置模拟引擎生成）

## 一、简介

WebSocket 数据源用于接入「服务端主动推送」的实时数据流。编辑器与数据服务之间建立一条长连接，服务端 whenever 数据变化就主动把最新值推给前端，无需前端反复请求，因此**实时性最好、延迟最低**，是 SCADA/WCS 监控画面中最常用的数据接入方式。

在编辑器内部，WebSocket 数据源遵循一套简单的「订阅/推送」约定：网关告诉服务端「我要订阅哪个数据点（topic）」，服务端就只推送这个点的数据。全部 7 类数据源（含 WebSocket）的演示与真实模式统一由桌面端 Rust 网关经 IPC 接管，前端不直连任何外部服务。

## 二、适用场景

适合以下情况优先选择 WebSocket：

- 需要**秒级甚至更快**的实时刷新（如输送线速度、AGV 位置、实时电流/温度曲线）。
- 服务端已经提供 WebSocket 接口，或你希望自建一个推送服务。
- 一个画面里有大量测点需要同时高频刷新（长连接比轮询更省资源）。

如果你的服务端只提供 REST 接口、不支持长连接，请改用 [HTTP 轮询](../http/用户使用手册.md)；若希望服务端单向推送且不想处理重连逻辑，可考虑 [SSE](../sse/用户使用手册.md)。

## 三、快速开始（演示模式，3 步上手）

演示模式**无需任何真实设备与本地端口**：模拟数据由桌面端内置模拟引擎（Rust `DemoAdapter`）直接生成正弦波，经 Tauri IPC 推送给画面。启动桌面应用（`npx tauri dev`）后即可体验完整流程。

**第 1 步：创建数据源实例**

点击工具栏的「🔌 数据源管理」→「＋ 新增数据源」，填写：

- 名称：`内置WebSocket模拟源`（任意）
- 类型：选择 `WebSocket`
- 连接模式：选择 `演示模式`
- 地址：演示模式下无需填写（自动置空且不可编辑）
![img.png](img/img.png)

保存后，列表中即出现该数据源。

**第 2 步：把节点绑定到数据源**

在画布上选中一个节点（如仪表盘、数字标签），右侧属性面板切换到「数据绑定」标签页：

- 数据源：下拉选择刚创建的 `内置WebSocket模拟源`
- 点ID：填写 `sensor.temp.001`（任意字符串，内置模拟引擎会为每个点ID生成独立波形）；需要多个测点时可继续「＋ 添加点组」，首组为主点驱动节点显示，其余点写入节点明细
- 转换函数：留空即可

填写点ID后，面板底部显示「✅ 已启用数据绑定」。

**第 3 步：观察实时数据**

节点会立即开始刷新，显示一条平滑的正弦波数值（范围约 20~80，每秒更新）。不同点ID的波形相位不同，便于区分。

## 四、配置项说明

在「数据源管理」对话框中，WebSocket 类型只需配置：

| 字段 | 说明 | 示例 |
| --- | --- | --- |
| 名称 | 数据源显示名，绑定节点时在下拉框中展示 | `车间A-实时流` |
| 类型 | 选择 `WebSocket` | — |
| 地址 | WebSocket 服务地址，必须以 `ws://` 或 `wss://` 开头 | `ws://192.168.0.10:8080/ws` |
| 备注 | 可选，描述用途 | `输送线实时遥测` |

> 桌面版全部数据源（含 WebSocket）统一由 Rust 网关经 Tauri IPC 接管：真实模式下由 Rust `WebSocketAdapter` 作为 WS 客户端连接你的服务地址（WebView 不直连）；演示模式则由内置 `DemoAdapter` 生成数据。两种模式前端链路完全一致，切换无需改绑定。

## 五、点ID（数据点地址）填写规则

点ID是前端与服务端之间的「订阅主题」，二者必须一致才能收到数据。

- 演示模式：点ID可以是任意字符串（如 `sensor.temp.001`、`line.speed`），内置模拟引擎会为每个不同的点ID生成一条独立的正弦波。
- 接入真实服务：点ID必须与你的服务端约定的 topic 完全一致。

服务端推送的数据帧中，编辑器按以下优先级识别点ID与数值：

- 点ID：`topic` → `id` → `pointId`
- 数值：`value` → `data`

因此你的服务只要保证推送 JSON 中含有 `topic`（或 `id`）与 `value` 字段即可被正确解析。

## 六、实际案例：输送线实时速度监控

**场景**：监控画面中有一条输送线，需要实时显示其运行速度（m/min），并在速度超过 60 时高亮告警。假设现场已有一台 WebSocket 服务 `ws://192.168.1.20:9000/telemetry`，会以 `topic=conveyor.01.speed` 每秒推送速度值。

**操作步骤**：

1. 数据源管理 → 新增数据源：
   - 名称：`输送线遥测服务`
   - 类型：`WebSocket`
   - 地址：`ws://192.168.1.20:9000/telemetry`
2. 画布上放置一个「数字标签」节点，选中它，在「数据绑定」标签页：
   - 数据源：`输送线遥测服务`
   - 点ID：`conveyor.01.speed`
   - 转换函数：`(raw) => Math.round(raw * 10) / 10`（保留一位小数）
3. 切换到「事件」标签页，添加一条规则：当 `value > 60` 时，将节点颜色设为红色（具体事件配置见事件功能文档）。

**预期效果**：数字标签每秒刷新当前速度并保留一位小数；速度超过 60 时节点变红，恢复后自动还原。

## 七、接入自己的 WebSocket 服务

将地址改为你自己的服务即可，编辑器对服务端只有两点约定：

1. **接收订阅消息**：网关连接成功后会发送
   ```json
   { "action": "subscribe", "topic": "conveyor.01.speed" }
   ```
   取消订阅时发送 `{ "action": "unsubscribe", "topic": "..." }`。
2. **推送数据帧**：服务端按任意频率推送
   ```json
   { "topic": "conveyor.01.speed", "value": 42.5, "timestamp": 1730000000000, "quality": "good" }
   ```
   其中 `timestamp`（毫秒）与 `quality`（`good`/`bad`/`uncertain`）可省略，省略时分别取当前时间与 `good`。

## 八、常见问题

**Q：节点一直不刷新数据？**
依次检查：① 数据源地址是否正确且服务已启动；② 网关监控面板中该数据源是否显示已连接（未连接时查看桌面应用日志的 `gateway_websocket` 通道定位）；③ 节点「点ID」是否与服务端推送的 `topic` 完全一致（区分大小写）；④ 若为 `wss://` 加密连接，确认服务端证书有效。

**Q：服务断开后会自动重连吗？**
会。网关引擎采用指数退避自动重连（2s 起、最长 30s），重连成功后自动重新订阅之前的所有点ID，无需手动干预。

**Q：一个数据源能被多个节点共用吗？**
可以。多个节点绑定同一个数据源实例时，编辑器内部只建立一条连接，按各自点ID分别订阅，互不影响。

## 九、注意事项

- 生产环境建议使用 `wss://`（加密）地址，避免数据被窃听或篡改。
- 点ID命名建议采用分层结构（如 `区域.设备.测点`），便于维护与排查。
- 若服务端推送频率极高（如每秒上百次），建议在服务端做节流，或在前端用转换函数降采样，避免画面频繁重绘。
