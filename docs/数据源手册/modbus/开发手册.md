# Modbus 数据源 · 开发手册

> 面向维护、调试或扩展 Modbus 数据接入的开发者。数据源类型标识：`modbus` ｜ 桌面版实现：Rust `gateway-modbus`（tokio-modbus 0.13） ｜ 状态：✅ 已上线

## 一、架构与数据流

Modbus TCP 为原生 TCP 二进制协议，浏览器无法直连。桌面版经 Tauri IPC 交由 Rust 网关原生实现，全程无端口、无中间进程：

```
桌面版（当前实现）：
  X6 节点 ── useDataService ── IpcGatewayService ──IPC──▶ gateway_connect/subscribe（commands.rs）
                                                            │
                                                    gateway-engine 会话任务
                                                    （轮询 ≥200ms、失败退避重连）
                                                            │ trait DeviceAdapter
                                                            ▼
                                                    gateway-modbus（tokio-modbus）
                                                            │ Modbus TCP
                                                            ▼
                                                    真实从站 / 仿真从站

演示模式：
  config 判定为 demo ──▶ gateway-demo（DemoAdapter，按点位哈希派生确定性波形）
```

前端 WS 网关桥接实现（原 `ModbusService` / `GatewayService`）已随纯桌面化改造移除（可从 git 历史找回）；内置 Node 网关（原 `gateway/modbus-gateway.ts`，19100 端口）与 mock 桥接（8086）也已退役。

## 二、前端接缝

路由：`useDataService.getDataService` 对全部协议统一创建（不再区分工业/Web 协议，无浏览器分支）：

```ts
new IpcGatewayService(key, buildDeviceConfig('modbus', url, config), 'MODBUS')
```

配置映射（`src/platform/deviceConfig.ts` → Rust `DeviceConfig::Modbus`，camelCase serde）：

设备地址与其他协议一致，统一填在数据源 `url` 字段：`主机` 或 `主机:端口`（缺省端口 502）；旧数据源 `url` 为空时回退 `config.host` / `config.port`。

| 前端字段 | Rust 字段 | 默认值 |
| --- | --- | --- |
| `url`（`主机[:端口]`） | `host` / `port` | `127.0.0.1` / `502` |
| `config.unitId` | `unit_id` | `1` |
| `config.pollInterval` | `poll_interval_ms` | `1000`（引擎下限 200） |

演示判定：仅以 `config.demo === true` 为准（地址可为空） → 映射为 `{ protocol: 'modbus', isMock: true, profile? }`（演示模式不是独立协议）；波形默认正弦，可在数据源对话框「演示波形」中选择（存于 `config.profile`）。

`IpcGatewayService` 要点：构造即 `start()`（先 `listen` 两个事件再 `gateway_connect`）；连接就绪前登记的订阅进入 `pendingSubscriptions`，就绪后补发；`gateway://telemetry` 按 `deviceId` 过滤后分发到各点位回调。线圈布尔值原样透传为 `DataPoint.value`，由节点 transform 自行处理。

## 三、Rust 侧实现（gateway-modbus）

### 点 ID 解析

`holding:N` / `input:N` / `coil:N` / `discrete:N`，N 为 0 基十进制地址；非法前缀或非数字地址返回 `GatewayError::InvalidPoint`（该点标记 bad，不影响其他点）。

### 批量读优化

每轮询周期：按数据区分组 → 组内按地址排序 → `merge_ranges` 合并地址连续段（寄存器段上限 `MAX_REGS_PER_READ = 125`，位段上限 `MAX_BITS_PER_READ = 1900`）→ 每段一次 Modbus 请求（FC03/FC04/FC01/FC02）→ 拆回各点遥测。N 个连续点位只产生 1 次网络往返。

### 值类型

- 寄存器（holding/input）：每点 1 个 16 位字 → JSON number（0~65535）
- 位（coil/discrete）：JSON boolean

### 连接生命周期

`connect` 经 `connect_slave(host:port)` 建立 TCP 并绑定 `Slave(unit_id)`；每实例独占连接，由单个会话任务持有。读取失败抛出 `GatewayError::Read`，由引擎统一处理（状态翻转事件 + 指数退避重连 2s→30s）。

## 四、IPC 协议速查

| 方向 | 名称 | 载荷 |
| --- | --- | --- |
| 命令 | `gateway_connect` | `{ deviceId, config: { protocol:'modbus', host, port, unitId, pollIntervalMs } }`（演示模式另带 `isMock:true` 与可选 `profile`） |
| 命令 | `gateway_subscribe` / `gateway_unsubscribe` | `{ deviceId, pointId }` |
| 命令 | `gateway_disconnect` | `{ deviceId }` |
| 事件 | `gateway://status` | `{ deviceId, connected, message }`（仅状态翻转时发送） |
| 事件 | `gateway://telemetry` | `{ deviceId, points: [{ pointId, value, timestamp, quality }] }`（每周期合批） |

## 五、测试与调试

```bash
cd src-tauri
cargo test -p gateway-modbus    # 点 ID 解析、连续段合并、批量上限切分（4 项）
cargo test -p gateway-engine    # DemoAdapter 全链路集成测试（含重连退避）
```

手工冒烟：`npx tauri dev` → 新增 Modbus 真实数据源指向任意从站（或 pymodbus 等仿真从站）→ 监控面板确认状态翻转与点位值。监控探针使用 `mon:<数据源id>` 前缀的独立会话，与业务会话互不干扰。

## 六、扩展方向

- **多寄存器数据类型**：当前每点 1 个字；32 位浮点/整数（2 字）、字节序（ABCD/CDAB）需在点 ID 语法与 `read` 拆值处扩展（建议语法如 `holding:100.float32`，并纳入点位解析测试）。
- **写操作**：引擎与适配器当前只读；写支持需扩展 `DeviceAdapter` trait、IPC 命令与前端绑定层下发接口。
- **连接复用**：当前每会话一条 TCP；同一网关设备多从站场景目前以多个数据源实例承载。
