# HTTP 轮询 数据源 · 用户使用手册

> 适用版本：roc-wes 编辑器 ｜ 数据源类型标识：`http` ｜ 内置模拟地址：`http://localhost:8081/api/data`

## 一、简介

HTTP 轮询数据源用于接入「请求/响应」式的 REST 接口。编辑器按固定间隔主动向你的接口发起 GET 请求，读取最新值。它不要求服务端支持长连接，**兼容性最好**——只要有一个能返回 JSON 的 HTTP 接口就能接入。

代价是实时性弱于 WebSocket/SSE（取决于轮询间隔），且每次都要建立请求，测点很多或频率很高时网络开销更大。

## 二、适用场景

适合以下情况选择 HTTP 轮询：

- 服务端只提供 REST/HTTP 接口，没有 WebSocket 或 SSE。
- 数据变化不快，秒级（2~5 秒）刷新即可满足（如环境温湿度、库存计数、设备运行状态位）。
- 对接第三方系统、MES/ERP 开放的查询接口。

若需要更快的实时性且服务端可改造，优先考虑 [WebSocket](../websocket/用户使用手册.md) 或 [SSE](../sse/用户使用手册.md)。

## 三、快速开始（演示模式，3 步上手）

开发环境（`npm run dev`）会自动启动内置 HTTP 模拟服务（`http://localhost:8081/api/data`）。

**第 1 步：创建数据源实例**

「🔌 数据源管理」→「＋ 新增数据源」：

- 名称：`内置HTTP轮询模拟源`
- 类型：`HTTP 轮询`
- 地址：`http://localhost:8081/api/data`（点「填入」可自动补全）

**第 2 步：绑定节点**

选中节点 → 属性面板「数据绑定」标签页：

- 数据源：选择 `内置HTTP轮询模拟源`
- 点ID：`env.humidity.01`（任意字符串，会作为 `pointId` 查询参数传给接口）
- 转换函数：留空

**第 3 步：观察数据**

节点立即刷新，显示一个在 0~100 之间缓慢漂移的数值（随机游走），默认每 2 秒更新一次。

## 四、配置项说明

| 字段 | 说明 | 示例 |
| --- | --- | --- |
| 名称 | 数据源显示名 | `车间环境接口` |
| 类型 | `HTTP 轮询` | — |
| 地址 | 接口基础地址（不含 pointId 参数） | `http://192.168.0.30:8000/api/data` |
| 备注 | 可选 | `温湿度查询` |

> 编辑器会在该地址后自动追加 `?pointId=<点ID>`（若地址已含 `?` 则用 `&` 连接）。HTTP 轮询同样**无需独立网关**，浏览器直接发起请求。

## 五、点ID与接口约定

点ID会作为查询参数 `pointId` 传给接口。服务端需返回如下 JSON：

```json
{ "id": "env.humidity.01", "value": 63.4, "timestamp": 1730000000000, "quality": "good" }
```

编辑器解析时：点ID取 `id`（缺省用订阅的点ID），数值取 `value`（兼容 `data`），`timestamp`/`quality` 可省略。

## 六、实际案例：仓库温湿度看板

**场景**：仓库有一个温湿度传感器网关，提供 REST 接口 `http://10.0.0.5:8080/sensor`，支持 `?pointId=xxx` 查询，返回当前温湿度。需要在画布上分别显示 3 个区域的湿度。

**操作步骤**：

1. 数据源管理 → 新增：名称 `仓库传感器`，类型 `HTTP 轮询`，地址 `http://10.0.0.5:8080/sensor`。
2. 放置 3 个数字标签节点，分别绑定该数据源，点ID填 `zone.A.humidity`、`zone.B.humidity`、`zone.C.humidity`。
3. 如需把返回的字符串转成整数显示，转换函数填 `(raw) => Math.round(raw)`。

**预期效果**：3 个标签每 2 秒各自刷新对应区域的湿度值。

> 提示：三个节点共用同一个数据源实例，但每个点ID独立轮询（各自一个定时器）。

## 七、接入自己的 HTTP 接口

只需保证接口满足：

1. 接受 GET 请求，URL 形如 `你的地址?pointId=<点ID>`。
2. 返回 `Content-Type: application/json`，正文含 `value` 字段。
3. 若前端与接口不同源，接口需允许跨域（返回 `Access-Control-Allow-Origin`）。内置模拟服务已默认开启 CORS。

## 八、常见问题

**Q：刷新太慢/太快怎么调？**
轮询间隔由服务实现决定（内置默认 2 秒）。如需为某数据源自定义间隔，可由开发侧在创建 `HttpPollingService` 时传入 `interval`（见开发手册）。

**Q：控制台报 CORS / Failed to fetch？**
通常是跨域被拒或接口不可达。确认接口已开启 CORS、地址与端口正确、服务已启动。

**Q：返回的 value 是字符串怎么办？**
在「转换函数」里转换，如 `(raw) => Number(raw)`。

## 九、注意事项

- 轮询会持续产生请求，测点多时注意服务端负载与网络带宽。
- 对实时性敏感的关键告警信号，不建议用低频轮询，改用 WebSocket/SSE 或工业协议网关。
- 接口应保证幂等（GET 只读），避免轮询触发副作用。
