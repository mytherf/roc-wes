# 从零搭建仓储自动化 SCADA 组态平台（三）：多协议数据接入体系

> 本系列第 3 篇，聚焦数据接入层：如何用一套 `IDataService` 接口统一 7 种异构协议，工业协议在 Tauri 桌面运行时下的 Rust 原生网关 + IPC 接入设计，模拟数据服务的特征化生成，以及数据绑定的 Transform 机制。

![7 种协议统一接入架构](images/03-multi-protocol.svg)

## 一、问题：7 种协议，一套接口

仓储自动化场景下，数据来源极其异构：WebSocket 推送传感器数据、HTTP 轮询 REST 接口、SSE 接收服务端事件、MQTT 订阅 IoT 设备主题——这 4 种是浏览器原生支持的。但工业现场还有 S7comm（西门子 PLC）、OPC UA（多厂商标准）、Modbus TCP（通用仪表/PLC）——这 3 种是原生 TCP 协议，浏览器根本无法直连。

7 种协议，连接方式、消息格式、订阅模型各不相同。但站在节点组件的角度，它们的需求很简单：**给我一个数据点的实时值**。

这就是 `IDataService` 接口的设计动机：

```typescript
// services/DataService.ts
export interface IDataService {
  /** 订阅一个数据点，回调接收实时更新 */
  subscribe(pointId: string, callback: (point: DataPoint) => void): void

  /** 取消订阅 */
  unsubscribe(pointId: string): void

  /** 当前是否已连接 */
  isConnected(): boolean

  /** 断开连接，释放资源 */
  disconnect(): void
}

export interface DataPoint {
  id: string
  value: number | string
  timestamp: number
  quality?: 'good' | 'bad' | 'uncertain'
}
```

4 个方法，覆盖所有协议的公共操作。无论底层是 WebSocket 长连接、HTTP 定时拉取、MQTT 主题订阅还是 S7 变量读取，节点组件只需要调用 `subscribe(pointId, callback)` 就能拿到统一的 `DataPoint` 流。

## 二、7 种实现

### 浏览器原生协议（4 种直连）

**WebSocketService**：最直接的实现。`subscribe` 时发送 `{ action: 'subscribe', topic: pointId }`，监听消息并分发给回调。内置自动重连和心跳。

**HttpPollingService**：定时 `fetch` 拉取。`subscribe` 启动一个 `setInterval`（默认 1000ms），每次请求 `GET /api/data?pointId=xxx`，把响应包装为 `DataPoint`。`unsubscribe` 清除定时器。

**SseService**：利用浏览器原生 `EventSource`。`subscribe` 时创建 EventSource 连接，`onmessage` 解析数据。SSE 的优势是自动重连和标准 HTTP 语义。

**MqttService**：基于 `mqtt.js` over WebSocket。`subscribe` 时调用 `client.subscribe(topic)`，`message` 事件分发。MQTT 的通配符主题（`device/+/status`）在这里天然支持。

### 工业协议（3 种：桌面运行时走 Rust 原生网关）

S7comm / OPC UA / Modbus TCP 是原生 TCP 协议，浏览器无法直连。早期版本通过独立的 Node.js 网关进程桥接为 WebSocket；迁移到 Tauri 2 后，这条链路被彻底重构：**Rust 侧同进程运行网关引擎，前端经 Tauri IPC 订阅数据**，不再有独立进程和本地端口。

前端入口是 `IpcGatewayService`，它实现了与 WebSocketService 相同的 `IDataService` 接口，对上层完全透明：

```typescript
// services/IpcGatewayService.ts（Tauri 桌面运行时专用）
import { invoke } from '@tauri-apps/api/core'   // 调用 Rust 侧命令
import { listen } from '@tauri-apps/api/event'  // 监听 Rust 侧事件

export class IpcGatewayService implements IDataService {
  private callbacks = new Map<string, DataCallback[]>()
  /** 连接建立前登记的订阅，待就绪后补发（connect 是异步的） */
  private pendingSubscriptions = new Set<string>()
  private ready = false

  private async start() {
    // 监听状态与遥测事件（只处理本设备会话的消息）
    await listen('gateway://status', (e) => {
      if (e.payload.deviceId !== this.deviceId) return
      this.connected = e.payload.connected
    })
    // Rust 每轮询一次批量推送一批点值，减少 IPC 开销
    await listen('gateway://telemetry', (e) => {
      if (e.payload.deviceId !== this.deviceId) return
      for (const p of e.payload.points) {
        const cbs = this.callbacks.get(p.pointId)
        cbs?.forEach(cb => cb({
          id: p.pointId, value: p.value,
          timestamp: p.timestamp, quality: p.quality,
        }))
      }
    })
    // 请求 Rust 建立设备会话
    await invoke('gateway_connect', { deviceId: this.deviceId, config: this.config })
    this.ready = true
    // 补发连接建立前登记的订阅
    for (const pointId of [...this.pendingSubscriptions]) {
      this.pendingSubscriptions.delete(pointId)
      await invoke('gateway_subscribe', { deviceId: this.deviceId, pointId })
    }
  }

  subscribe(pointId: string, callback: DataCallback) {
    if (!this.callbacks.has(pointId)) this.callbacks.set(pointId, [])
    this.callbacks.get(pointId)!.push(callback)
    if (this.ready) void invoke('gateway_subscribe', { deviceId: this.deviceId, pointId })
    else this.pendingSubscriptions.add(pointId)
  }
  // unsubscribe / disconnect 对称：移除回调 + invoke 通知 Rust
}
```

### IPC 网关协议

前端与 Rust 网关之间约定了四个命令 + 两个事件：

```
前端 → Rust（invoke 命令）:
  gateway_connect     { deviceId, config }   // 建立设备会话
  gateway_subscribe   { deviceId, pointId }  // 订阅数据点
  gateway_unsubscribe { deviceId, pointId }  // 取消订阅
  gateway_disconnect  { deviceId }           // 销毁会话

Rust → 前端（事件推送）:
  gateway://status    { deviceId, connected, message }
  gateway://telemetry { deviceId, points: [{ pointId, value, timestamp, quality }] }
```

Rust 侧采用六边形架构的 workspace：`gateway-core` 定义领域模型（DeviceConfig / DeviceAdapter trait / 遥测与错误类型），`gateway-engine` 编排会话（连接/轮询/断线重连），`gateway-modbus` 用 tokio-modbus 实现真实 Modbus TCP 适配器，`gateway-demo` 提供演示模式适配器。新增协议只需在组合根 `factory.rs` 加一个 match 分支。

项目定位为纯桌面版（必须 `npx tauri dev` 启动），工业协议不再有浏览器分支：旧的 `GatewayService` 抽象基类 + WS 桥接实现（S7Service / OpcService / ModbusService，曾服务于自备外部网关的场景）已移除，可从 git 历史找回。现在演示模式与工业协议统一由 `IpcGatewayService` 接管，上层代码无感知。

## 三、服务工厂与缓存

`useDataService` 组合式函数是连接节点和数据服务的桥梁。它维护了一个服务实例缓存，避免对同一个端点建立多条连接：

```typescript
// composables/useDataService.ts
/** 工业协议类型：浏览器无法直连（原生 TCP），统一走 Rust 原生网关 */
const INDUSTRIAL_TYPES = new Set(['s7', 'opc', 'modbus'])

const dataServiceMap = new Map<string, IDataService>()

function getDataService(
  sourceType: string,
  sourceUrl?: string,
  sourceConfig?: Record<string, any>
): IDataService | null {
  if (!sourceUrl) return null // 未绑定数据源 → 不订阅，节点保持静态值

  // 缓存键含设备配置：区分同地址不同设备（如同一地址不同 unitId）
  const key = `${sourceType}:${sourceUrl}:${sourceConfig ? JSON.stringify(sourceConfig) : ''}`
  if (dataServiceMap.has(key)) return dataServiceMap.get(key)!

  // 演示模式数据源与工业协议统一经 Rust 原生网关（IPC）
  if (isDemoSource(sourceType, sourceUrl, sourceConfig) || INDUSTRIAL_TYPES.has(sourceType)) {
    const service = new IpcGatewayService(
      key,
      buildDeviceConfig(sourceType, sourceUrl, sourceConfig),
      sourceType.toUpperCase()
    )
    dataServiceMap.set(key, service)
    return service
  }

  let service: IDataService | null = null
  switch (sourceType) {
    case 'websocket': service = new WebSocketService(sourceUrl); break
    case 'http':      service = new HttpPollingService(sourceUrl, sourceConfig?.interval); break
    case 'sse':       service = new SseService(sourceUrl); break
    case 'mqtt':      service = new MqttService(sourceUrl); break
    // 工业协议（s7 / opc / modbus）已在上方统一路由到 IpcGatewayService
    default:          return null // 不支持的类型 → 不订阅数据
  }

  dataServiceMap.set(key, service)
  return service
}
```

当 10 个节点都订阅同一个 WebSocket 端点的不同数据点时，只有 1 个 WebSocket 连接、1 个 `WebSocketService` 实例。`subscribe` 只是注册回调，`unsubscribe` 只是移除回调——连接始终复用。

### 绑定与解绑

```typescript
function bindNodeData(node: Node) {
  const binding = node.getData()?.binding as DataBindingConfig | undefined
  if (!binding?.pointId) return

  unbindNodeData(node.id)  // 先取消旧订阅，避免重复绑定

  // 解析数据源：优先 sourceId（数据源管理实例），回退旧字段，否则模拟数据
  let sourceType = binding.sourceType
  let sourceUrl = binding.sourceUrl
  let sourceConfig: Record<string, any> | undefined
  if (binding.sourceId) {
    const ds = dataSourceStore.getDataSource(binding.sourceId)
    if (ds) {
      sourceType = ds.type
      sourceUrl = ds.url
      sourceConfig = ds.config
    }
  }

  const service = getDataService(sourceType ?? 'websocket', sourceUrl, sourceConfig)
  if (!service) return

  // transform 是 Function 无法序列化，运行期从 transformSource 编译（编译结果缓存回 binding）
  const transform = resolveTransform(binding)

  service.subscribe(binding.pointId, (point) => {
    const currentData = node.getData()
    // transform 单参数（raw），输出整体写入 node.data.value（不展开合并）
    const newValue = transform ? transform(point.value) : point.value
    const nextData = {
      ...currentData,
      value: newValue,
      _timestamp: point.timestamp,
      _quality: point.quality,
    }
    node.setData(nextData)
    // 评估节点事件规则（上升沿/下降沿触发告警）
    evaluateNodeEvents(node.id, currentData, nextData)
  })

  nodeDataSubscriptions.set(node.id, binding.pointId)
}
```

`unbindAllNodes()` 取消所有订阅但保留连接（用于画布重载），`dispose()` 则断开所有连接、清空缓存（用于组件卸载）。

## 四、模拟数据服务：特征化生成

开发阶段不可能每次都接真实 PLC。全部 7 类协议的演示模式均由桌面端 Rust `DemoAdapter` 生成（经 IPC 推送，链路与真实设备完全一致），且每种协议的波形各具**数据特征**：

| 协议 | 默认波形（profile） | 数据特征 | 视觉表现 |
|------|----------|----------|----------|
| WebSocket | `Websocket` | 正弦波 20~80 | 平滑周期波动 |
| HTTP 轮询 | `Http` | 随机游走 | 缓慢漂移 |
| SSE | `Sse` | 锯齿斜升 | 线性增长后归零 |
| MQTT | `Mqtt` | 离散档位 | 跳变 |
| S7 / OPC UA / Modbus | 默认正弦 | 与 Web 协议同构的模拟曲线 | 与真实链路同构 |

> 注：演示模式以数据源配置 `config.demo = true` 标识，无需填写地址，不占用任何端口；波形默认跟随协议特征，也可在数据源对话框「演示波形」中任选一种（存于 `config.profile`）。

这些特征数据不是简单的随机数——每种协议的数据模式都模拟了真实工业场景中的典型信号。这样在演示时，仪表盘的正弦波、折线图的锯齿、输送线的阶梯跳变，看起来就像真实设备在运行。

演示数据在桌面端进程内生成：gateway-engine 的会话任务按轮询周期调用 `DemoAdapter.read()`，遥测经 `gateway://telemetry` 事件批量推回前端。零端口占用，`npx tauri dev` 启动即用，无需预启任何模拟服务；Node 版 mock 服务（原 `mock/` 目录，曾占用 8080~8083 端口）已移除。

## 五、数据绑定的 Transform 机制

节点拿到原始数据值后，通常不能直接使用——`holding:100` 的 Modbus 寄存器值是 0~100 的整数，但堆垛机节点需要的是 `{ status: 'running', isMoving: true, progress: 0.75 }` 这样的业务状态。

**Transform 函数**就是这个映射层：

```typescript
// 堆垛机的 transform：按数值分档映射为设备状态
(raw) => {
  const v = Number(raw)
  if (v < 20) return { status: 'idle', isMoving: false, progress: 0 }
  if (v < 60) return { status: 'running', isMoving: true, progress: ((v - 20) / 40) * 100 }
  if (v < 80) return { status: 'warning', isMoving: false, progress: 0 }
  return { status: 'error', isMoving: false, progress: 0 }
}

// 货架的 transform（自包含、无闭包：每次刷新重新生成三维货位状态）
(_raw) => {
  const floors = 4, rows = 1, cols = 6
  const floorGrids = Array.from({ length: floors }, () =>
    Array.from({ length: rows }, () =>
      Array.from({ length: cols }, () => {
        const rand = Math.random()
        const status = rand < 0.3 ? 'empty' : rand < 0.6 ? 'occupied' : 'reserved'
        return { status }
      })))
  return { floorGrids }
}
```

Transform 的输入是单个 `raw`（原始值），输出整体写入节点的 `node.data.value`（不展开合并到 data 顶层）。节点 Vue 组件通过 `useNodeData` 读取 `value` 等字段并监听 `change:data` 增量同步，刷新视觉表现；同时每次数据写入都会触发节点事件规则的边沿评估。

### Transform 的持久化

如第 2 篇所述，函数不能 JSON 序列化。项目采用 `transform`（运行时）+ `transformSource`（字符串）双字段策略。保存项目时序列化 `transformSource`，加载时由 `resolveTransform` 用 `new Function('raw', 'return (src)(raw)')` 重编译并缓存。这要求 transform 函数**闭包无关**——所有常量必须内联。

## 六、数据源管理 UI

`DataSourceDialog.vue` 提供了一个统一的管理界面，用户可以：

1. **创建数据源实例**：选择协议类型、填写连接参数（URL / 主机 / 端口 / 机架 / 插槽等）
2. **切换演示/真实模式**：一键在模拟服务和真实网关之间切换
3. **实时连通性探测**：`GatewayMonitorService` 定时检测每个数据源的连接状态、建连耗时、数据点实时值
4. **错误告警**：连接失败、数据质量异常时在监控面板高亮显示

数据源实例存储在 `dataSourceStore` 中，节点绑定通过 `sourceId` 引用实例，而不是内嵌连接参数。这意味着修改一个数据源的 URL，所有引用它的节点自动生效。

## 七、架构全景

```
节点组件
  │
  ├── binding.sourceType = 'websocket'  →  WebSocketService 直连
  ├── binding.sourceType = 'mqtt'       →  MqttService 直连
  ├── binding.sourceType = 's7'         →  IpcGatewayService → IPC → Rust 网关 → TCP → PLC
  └── binding.sourceType = 'modbus'     →  IpcGatewayService → IPC → Rust 网关 → TCP → 从站
          │
          ▼
    IDataService.subscribe(pointId, callback)
          │
          ▼
    DataPoint { id, value, timestamp, quality }
          │
          ▼
    transform(raw) → 业务状态
          │
          ▼
    node.setData({ value, _timestamp, _quality }) → Vue 组件响应式更新
```

无论数据来自哪种协议，最终都走同一条路径：`subscribe → DataPoint → transform → setData → Vue 渲染`。这就是统一抽象的价值——新增一种协议只需要实现 `IDataService` 接口（桌面侧再加一个 Rust 适配器），节点组件完全不用改。
