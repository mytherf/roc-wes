# roc-wes 开发指南

面向开发者的环境搭建、日常命令、架构要点与协议扩展指南。单协议实现细节见 [数据源手册](../数据源手册/roc-wes%20数据源手册.md)，桌面版架构决策见 [Tauri 目标架构](./tauri-目标架构.md)。

## 1. 环境要求

| 工具 | 版本 | 用途 |
| --- | --- | --- |
| Node.js | ≥ 22 | 前端构建与前端测试 |
| Rust stable | ≥ 1.95（rustc / cargo） | 桌面版网关与壳 |
| tauri-cli | 随 `@tauri-apps/cli`（devDependency） | `npx tauri dev/build` |
| WebView2 Runtime | Windows 10/11 一般已内置 | 桌面版渲染 |
| OpenSSL Dev（仅开发者构建需要） | ShiningLight Win64 完整版 | S7 / OPC UA 适配器的 TLS 依赖（静态链接） |

### 1.1 OpenSSL 构建前提（仅开发者，最终用户无需安装）

`gateway-opcua`（opcua crate）经 openssl-sys 引入 TLS 依赖。项目采用**静态链接**：构建期将 `libssl_static` / `libcrypto_static` 编入可执行文件，发布产物自包含、运行时无需任何 OpenSSL DLL——因此最终用户安装 NSIS 包后开箱即用，**只有克隆源码编译的开发者**需先安装一次：

```powershell
# 必须装 Dev 完整版（Light 版只有运行时 DLL，缺 lib/include 无法编译）
winget install ShiningLight.OpenSSL.Dev
```

默认安装于 `C:\Program Files\OpenSSL-Win64`。链接参数已固化在仓库根 `.cargo/config.toml`（`OPENSSL_LIB_DIR` 指向 `lib\VC\x64\MD` + `OPENSSL_STATIC=1` + `OPENSSL_LIBS=libssl_static:libcrypto_static`），装到默认位置后无需手动设环境变量；装到其他位置则需改该文件或用同名环境变量覆盖。

> ⚠️ 终端残留的 `OPENSSL_*` 环境变量优先于 `.cargo/config.toml`，会静默覆盖配置；若曾手动设过，构建前先 `Remove-Item Env:OPENSSL_*`。

## 2. 日常命令

```bash
# 前端（项目根目录）
npm install
npm run build        # vue-tsc 类型检查 + vite build → dist/
npx vitest run       # 前端测试（vitest + jsdom，点组机制 / 属性面板交互）

# 桌面（项目根目录，唯一开发入口）
npx tauri dev        # 自动先跑 npm run dev（vite，端口 1420），再编译启动桌面应用
npx tauri build      # 产出 NSIS 安装包（src-tauri/target/release/bundle/nsis/）

# Rust 网关（src-tauri/ 目录）
cd src-tauri
cargo check --workspace
cargo test --workspace                  # 单元测试 + 集成测试（当前 11 项全绿）
cargo clippy --workspace --all-targets  # 零警告基线，PR 前必跑
```

项目为纯桌面版，开发态与生产态均**不监听任何本地数据端口**（vite dev server 的 1420 除外）：全部 7 类协议的演示模式由 Rust `DemoAdapter` 按协议 profile 生成特征波形；`BUILTIN_MOCK_URLS` 中的 `ws://localhost:8080/ws` 等地址仅作**演示模式标识**（表单预填与历史数据源识别），背后无本地服务。

## 3. 代码版图

前端（`../../src`）分层：

- `components/`：X6 节点组件、画布、属性面板、数据源对话框等 UI
- `services/`：各协议 `IDataService` 实现 + `GatewayMonitorService` 探针 + `IpcGatewayService`（IPC 客户端）
- `composables/useDataService.ts`：**数据服务路由中心**——按协议类型与演示判定选择实现
- `platform/`：桌面平台接缝。`deviceConfig.ts` 把数据源配置映射为 Rust `DeviceConfig`（含演示模式判定）；`fileStorage.ts` 是全部工程数据的文件落盘统一入口（见 5.6）；`routeWindow.ts` 打开路线编辑器独立 OS 窗口
- `stores/`：editor（画布）、dataSource（数据源，自动持久化）、route、theme（四者均经 `fileStorage` 落盘）

Rust workspace（`../../src-tauri/crates`，六边形架构）：

| crate | 职责 | 依赖方向 |
| --- | --- | --- |
| `gateway-core` | 领域模型：`DeviceConfig` / `Telemetry` / `trait DeviceAdapter` / 错误类型 | 最内层，无外部框架依赖 |
| `gateway-engine` | 会话编排：每设备一个 tokio 任务，轮询、状态去抖、失败退避重连；经 `trait EventSink` 输出，Tauri 无关 | core |
| `gateway-modbus` | Modbus TCP 适配器（tokio-modbus 0.13） | core |
| `gateway-demo` | 演示适配器（模拟曲线） | core |

壳层（`../../src-tauri/src`）：`commands.rs`（4 个 IPC 命令）、`factory.rs`（配置 → 适配器，**新增协议的唯一组合根**）、`state.rs`（`AppState`：引擎 + 事件发射器）、`lib.rs`（事件分发与退出清理）。

## 4. 桌面数据链路

IPC 命令（camelCase 参数，语义对齐旧 WS 网关协议，但无任何本地端口）：

| 命令 | 语义 |
| --- | --- |
| `gateway_connect(deviceId, config)` | 创建会话，异步连接，结果经事件通知 |
| `gateway_subscribe(deviceId, pointId)` | 订阅数据点 |
| `gateway_unsubscribe(deviceId, pointId)` | 取消订阅 |
| `gateway_disconnect(deviceId)` | 断开并销毁会话 |

事件：

- `gateway://status` — `{ deviceId, connected, message }`，仅在连接状态翻转时发送（去抖）
- `gateway://telemetry` — 每轮询周期合批发送的点位数据

引擎机制要点（`gateway-engine`）：

- 轮询间隔下限 `MIN_POLL_INTERVAL_MS = 200`
- 连接失败指数退避重连：2s 起、上限 30s；订阅 / 取消等控制指令会提前唤醒退避循环
- `deviceId` 全局唯一，重复 connect 返回 `AlreadyExists`；监控探针因此使用 `mon:<数据源id>` 前缀的独立会话

前端路由规则（`useDataService.getDataService`）：`s7 / opc / modbus` 三类工业协议与演示模式数据源统一走 `IpcGatewayService`；浏览器时代的旧 WS 桥接实现已移除（项目为纯桌面版，无浏览器分支）。演示模式判定在 `platform/deviceConfig.ts`：`config.demo === true` 或地址等于演示标识地址（`BUILTIN_MOCK_URLS`）即映射为 `{ kind: 'demo' }`。

## 5. 画面开发指南（节点 / 数据源 / 绑定 / 事件）

### 5.1 新增节点类型（三步）

以新增一个「我的设备」节点为例，只需改 3 个文件：

#### 第 1 步：创建节点组件 `src/components/nodes/MyNode.vue`

```vue
<!-- MyNode.vue - 我的设备节点 -->
<template>
  <!-- 极简模式（工具栏切到「图标模式」时）：统一由 NodeMinimalView 渲染图标+名称+状态色 -->
  <NodeMinimalView v-if="isMinimal" :icon="displayIcon" :icon-size="iconSize" :name="name" :status="status" />
  <!-- 完整模式：绘制你的自定义图形 -->
  <div v-else class="my-node">
    <div class="my-icon">
      <NodeIcon :icon="displayIcon" :size="iconSize" alt="我的设备" />
    </div>
    <span class="my-name">{{ name }}</span>
    <span class="my-status" :class="statusClass">{{ statusText }}</span>
  </div>
</template>

<script setup lang="ts">
import { useDisplayMode } from '@/composables/useDisplayMode'   // 极简/完整模式切换
import { useNodeIcon } from '@/composables/useNodeIcon'         // 图标解析（data.icon 优先，否则模板默认）
import { useNodeData } from '@/composables/useNodeData'         // 声明自定义属性（见 5.3）
import { useNodeStatus } from '@/composables/useNodeStatus'     // status → 颜色类名 + 中文文案
import NodeMinimalView from './NodeMinimalView.vue'
import NodeIcon from './NodeIcon.vue'

// @antv/x6-vue-shape 注入的 prop：X6 Node 实例
const props = defineProps<{ node: any }>()

const { isMinimal } = useDisplayMode(props.node)
const { displayIcon, iconSize } = useNodeIcon(props.node, 'my-node')
const { name, status, speed } = useNodeData(props.node, {
  name: '我的设备-01',
  status: 'idle',
  speed: 0,
})
const { statusClass, statusText } = useNodeStatus(status)
</script>
```

要点：

- `props.node` 是 X6 Node 实例，所有读写都经 `node.getData() / node.setData()`；
- 四个 composable 是节点组件的标准搭配：`useDisplayMode`（显示模式）、`useNodeIcon`（图标）、`useNodeData`（属性取数）、`useNodeStatus`（状态派生）；
- 需要对外暴露方法时用 `defineExpose`（如 GaugeNode 暴露 `updateValue`）。

#### 第 2 步：注册形状 `../../src/components/nodes/registry.ts`

```ts
import MyNode from './MyNode.vue'                       // 1. import 组件
// ...
const nodeRegistry = [
  // ...
  { shape: 'my-node', component: MyNode },              // 2. 登记 shape 名 → 组件
]
```

`shape` 名就是后面模板配置里的 `type`，必须完全一致。

#### 第 3 步：加入组件库模板 `../../src/components/nodes/nodeTemplates.ts`

```ts
{
  type: 'my-node',                 // 必须与 registry 中注册的 shape 一致
  label: '我的设备',               // 组件库显示名
  icon: '🔧',                      // 组件库图标
  group: 'WCS 设备',               // 组件库分组（基础 / WCS 设备 / IoT 监控）
  width: 160, height: 120,        // 拖入画布的默认尺寸
  pointIdTemplate: 'device.mynode',// 点位 ID 模板：拖入时自动生成唯一 pointId 并注入 binding
  data: { name: '我的设备-01', status: 'idle', speed: 0 },  // 默认数据（对象会被深拷贝）
  transform: (raw: any) => {       // 原始值 → 业务状态的转换函数
    const v = Number(raw)
    return v > 80 ? { status: 'error' } : { status: 'running' }
  },
}
```

`NodeTemplate` 其它可用字段：

- `data` 也可写为函数（每次拖拽返回全新对象，避免数组等引用类型共享，见分拣机 `chutes` 示例）；
- `buildData(pointId)`：完整自定义 data 构建（含 binding），货架节点即用此法（transform 需闭包引用随机货格时无法单独持久化）；
- `attrs` / `ports`：仅原生形状（rect/circle）使用，Vue 组件节点不需要。

可选：在 `nodeIcons.ts` 中为 `my-node` 添加默认图标（`useNodeIcon` 未找到时会回退为形状名文本）。

### 5.2 添加数据源

数据源是「数据从哪里来」的配置（一个 WebSocket 服务、一个 MQTT 主题、一台 Modbus PLC……），全局管理、自动持久化。

**界面方式（推荐）**：工具栏「数据源」按钮 → 数据源对话框中点击「添加」→ 选择类型（7 种）→ 填名称、地址与设备参数（或勾选演示模式）→ 保存。数据自动落盘为应用配置目录下的 `datasources.json`，重启不丢。

**代码方式**：

```ts
import { useDataSourceStore, type DataSource } from '@/stores/dataSource'
const store = useDataSourceStore()

const ds: DataSource = store.addDataSource({
  name: '温度采集',
  type: 'websocket',            // websocket | mqtt | http | sse | s7 | opc | modbus
  url: 'ws://localhost:8080/ws',
  description: '车间温度',
  config: {},                   // 协议设备参数（如 Modbus 的 host/port/unitId/pollInterval）
})
// 其它 API：updateDataSource(id, updates) / deleteDataSource(id) / getDataSource(id)
```

注意：

- `s7 / opc / modbus` 三类工业协议在桌面版由 Rust 网关经 IPC 直连设备：地址填设备地址，连接参数（host/port/unitId/轮询间隔）放 `config`，由 `platform/deviceConfig.ts` 映射为 Rust `DeviceConfig`；
- 勾选「演示模式」或地址等于 `BUILTIN_MOCK_URLS` 内置地址时，桌面版自动路由到 Rust `DemoAdapter` 生成模拟数据。

### 5.3 添加节点自定义属性

节点属性保存在 `node.data` 对象里。组件内用 `useNodeData` 声明需要哪些字段及默认值：

```ts
// 声明 3 个属性；返回值均为响应式 ref，模板直接用 {{ name }} 即可
const { name, speed, alarm } = useNodeData(props.node, {
  name: '我的设备-01',
  speed: 0,
  alarm: false,
})
```

新增属性 = 在 `defaults` 对象中加一行（已存在属性面板会实时刷新：`useNodeData` 内部监听 X6 `change:data` 事件增量同步）。

属性面板「基础」页按**约定**自动渲染可编辑控件：

| node.data 字段 | 面板控件 |
| --- | --- |
| `label` | 标签输入框（所有节点） |
| `name` | 名称输入框（WCS 设备等） |
| `rows` / `cols` / `floors` | 货架维度数字框（存在才显示） |
| `data.title` / `data.status` | 卡片标题 + 状态下拉（卡片节点） |
| `icon` / `iconSize` | 图标选择 / 上传 / 尺寸滑杆 |

其它自定义属性：可直接在组件内自绘编辑 UI，或编程修改（`node.setData({ ...node.getData(), speed: 100 })`）。

### 5.4 绑定数据源（多点组）

**界面方式**：选中节点 → 属性面板「绑定」页 → 选择数据源（不选 = 无实时数据）→ 按组添加「点ID + 转换函数」→ 自动保存。一个节点可绑定多个点组，**首组为主点**，驱动节点渲染值。

底层写入 `node.data.binding`：

```ts
node.data.binding = {
  sourceId: 'ds-xxx',              // 数据源实例 ID（为空则不订阅，节点保持静态值）
  // 点组列表：每组 = 点 ID + 该点专属转换函数源码；首组为主点（points[0].pointId 即主点 ID）
  points: [
    { pointId: 'sensor.temp.001', transformSource: '(raw) => Math.round(raw)' },  // 主点（首组）
    { pointId: 'sensor.humi.001' },                                               // 附加点
  ],
}
```

⚠️ **转换函数持久化规则**：`transform` 是函数无法被 JSON 序列化，因此约定 `transformSource` 存放**自包含的箭头函数源码**（不引用任何外部变量），运行期由 `useDataService` 用 `new Function` 按需编译（`compileTransform`）。点组归一化在 `resolveBindingPoints`：取 `points`（去重去空），每点使用自己组内的转换函数。

**运行时链路**（`useDataService.bindNodeData`）：逐点订阅 → 每次推送 → 该点组内转换函数处理 → 全部点写入 `node.data.values[pointId]`（`{ value, timestamp, quality }`）→ 主点额外写入 `node.data.value`（附带 `_timestamp` / `_quality`）驱动节点渲染 → 触发事件评估（5.5）。退订（`unbindNodeData` / `rebindIfChanged`）按已订阅点列表逐一处理。

两条实现约束（改动相关代码前必读）：

- `value` / `_timestamp` / `_quality` / `values` 是**运行期遥测字段**，列于 `useGraphSync` 的 `RUNTIME_DATA_KEYS`，不参与画布 ↔ Store 全量对比。新增运行期写入字段必须同步加入该列表，否则遥测刷新会被误判为"实质变化"→ 整画布重建 → 节点数据回落旧快照（表现为数据丢失）。
- 向节点写 `binding` / `events` 等**整体替换**语义的字段必须用 `node.updateData(...)`（顶层替换，deep:false），不能用默认 `setData` 深合并——X6 深合并即 lodash.merge，数组按下标逐项合并（删除条目会残留尾部旧项）且跳过 undefined（旧字段清不掉）。

### 5.5 添加事件与触发

**界面方式**：选中节点 → 属性面板「事件」页 →「＋ 添加事件规则」。规则存储在 `node.data.events` 数组（草稿模式编辑，见 `useNodeEvents`）。

规则字段：

| 字段 | 说明 |
| --- | --- |
| `enabled` | 启用开关 |
| `name` | 规则名称（日志 / 告警展示用） |
| `field` | 监听的数据字段（留空 = 监听顶层 `value`） |
| `condition` | 触发条件：`changed`（值变化）/ `gt` / `lt` / `gte` / `lte` / `eq` / `neq` |
| `threshold` | 阈值（比较类条件使用） |
| `actionType` | 动作：`console`（控制台日志）/ `alert`（弹出告警）/ `http`（HTTP 请求） |
| `message` / `url` / `method` | 对应动作的参数 |

**触发语义**（`NodeEventService.evaluateNodeEvents`）：

- `changed`：每次字段值变化都触发；
- 比较类条件：**上升沿触发**——仅当从「不满足」变为「满足」时触发一次（内部以 `prevMatchState` 记录上次匹配状态），避免数据持续越限时重复告警（类似 PLC 报警）；
- 触发时机：数据绑定推送更新节点数据后自动评估；无绑定时可编程触发——`node.setData({ ...node.getData(), value: 90 })` 同样会走事件评估。

**新增动作类型**：在 `../../src/services/NodeEventService.ts` 的 `executeAction` 的 switch 中追加 case（如 websocket / mqtt 推送），并在 `EventActionType` 联合类型与属性面板「事件」页的动作下拉中同步补充即可。

### 5.6 数据持久化（文件落盘）

全部工程数据经 `../../src/platform/fileStorage.ts`（`readJsonFile` / `writeJsonFile`）以 JSON 文件存储：走 Tauri FS 写入应用配置目录（Windows 为 `%APPDATA%\com.rocwes.desktop\`），采用原子写入（先写 `.tmp` 再 rename 覆盖，防崩溃损坏）。无 localStorage 回退——非 Tauri 环境（如直接访问 vite dev server）读写会失败并打日志，因此开发必须经 `npx tauri dev` 启动。不引入存储适配层，新增持久化需求直接复用这两个工具函数。

| 文件 | 内容 | 保存时机 |
| --- | --- | --- |
| `editor.json` | 画布数据 + 选中状态 + 显示模式 | 工具栏「保存」手动 |
| `datasources.json` | 数据源列表 | 任何变更后自动 |
| `routes.json` | AGV 路线 | 任何变更后自动 |
| `theme.json` | 主题选择 | 切换主题时 |
| `run-preview.json` | 运行预览快照 | 工具栏「运行」时写入，`/run` 路由读取 |

fs 权限在 `../../src-tauri/capabilities/default.json`（`fs:allow-appconfig-read/write-recursive`），Rust 侧由 `lib.rs` 注册 `tauri-plugin-fs`。

## 6. 新增协议扩展指南

以新增 `gateway-xxx` 为例，改动点收敛、互不扩散：

1. **core**：`gateway-core/src/config.rs` 增加 `XxxConfig` 结构体（camelCase serde）与 `DeviceConfig::Xxx` 变体，补默认值函数；

3. **组合根**：`../../src-tauri/src/factory.rs` 增加一个 match 分支（引擎、命令层、事件层零改动）；
4. **前端**：`platform/deviceConfig.ts` 的 `buildDeviceConfig` 增加类型映射；若是全新协议类型，同步更新 `useDataService` 的 `INDUSTRIAL_TYPES`、数据源对话框与 `stores/dataSource.ts` 常量；
5. **文档**：`../数据源手册` 下新建该协议的用户使用手册 + 开发手册，并更新手册总索引。

验收基线：`cargo test --workspace` 与 `cargo clippy --workspace --all-targets` 全绿，`npm run build` 通过。

## 8. 常见问题

- **`tauri build` 报 `icons/icon.ico not found`**：Windows 资源编译必需该文件，位于 `../../src-tauri/icons`，勿删。
- **桌面版连接 S7 / OPC 报错**：两类适配器均已上线，可直连真实设备/服务器；连接失败优先核对设备参数（S7 的 rack/slot 与 PUT/GET、OPC UA 的端点 URL 与匿名策略），见 [S7 用户手册](../数据源手册/s7/用户使用手册.md) / [OPC UA 用户手册](../数据源手册/opc/用户使用手册.md) 常见问题章节。
- **编译报找不到 OpenSSL / `could not find native static library`**：见 1.1 节——安装 ShiningLight OpenSSL **Dev 完整版**，并检查终端是否有残留 `OPENSSL_*` 环境变量覆盖了仓库根 `.cargo/config.toml`。
- **演示标识地址（`ws://localhost:8080/ws` 等）用外部工具连不上**：属预期。这些地址仅作演示模式识别与表单预填，背后没有任何本地服务；演示数据由 Rust `DemoAdapter` 生成，真实数据请把数据源切到真实模式并填设备地址。
- **vite dev 端口为什么是 1420**：5173 在部分 Windows 机器上会落入 Hyper-V/WinNAT 动态保留端口范围导致 `EACCES`；1420 为 Tauri 官方推荐端口，`strictPort` 保证被占用时直接报错（与 `tauri.conf.json` 的 `devUrl` 一致）。
