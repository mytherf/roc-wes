# 演示模式自定义数据方案

> 状态：已实施（v2 2026-08-20；v3 2026-08-20；v4 2026-08-20：共享会话订阅引用计数，vitest 72/72、vue-tsc、vite build 全部通过）
> 范围：数据源管理（演示模式）新增「自定义数据」档位；演示模式点位语义调整；节点默认点ID 移除与复制独立性；共享会话订阅引用计数

## 1. 背景与目标

- 数据源管理的演示模式目前仅支持四种内置波形（sine / randomWalk / sawtooth / steps）。
- 需求：新增「自定义数据」选项，用户输入 JSON 格式数据（本期仅 JSON，后续扩展其他格式），演示引擎按点位分发该数据。
- 同步调整：演示模式**波形档**的点位 ID 固定为 `sample-point`，不再使用绑定时用户自填的点 ID；**自定义数据档**不使用 sample-point，点位 ID 即 JSON 顶层 key。

## 2. 现状盘点

Rust 侧已具备（含测试）：

- `gateway-core/config.rs`：7 个协议配置均带 `profile`（含 `DemoProfile::Custom`）与 `custom_data: Option<serde_json::Value>` 字段 + `demo_custom_data()` 访问器。
- `gateway-demo/lib.rs`：`DemoAdapter` 支持 Custom 档位（当前语义：整份 JSON 返回所有点位 → **本方案改为按 key 取值**）。
- `src-tauri/src/factory.rs`：`isMock` 时统一路由 `DemoAdapter::new(profile, custom_data)`。
- 前端 `IpcGatewayService.ts` 的 `DeviceConfig` 类型已含 `customData` 与 `'custom'`。

前端缺口：

1. `platform/deviceConfig.ts`：`DemoWave` 不含 `'custom'`，演示分支不下发 `customData`。
2. `DataSourceDialog.vue`：无自定义数据录入 UI（JSON 文本框 + 校验）。
3. `protocolConfigRegistry.buildDataSourceConfig`：保存的 config 不带 `customData`。
4. 绑定侧无演示模式点位语义（固定 sample-point / 按 key 绑定）。

## 3. 各协议流程（七协议完全统一）

演示模式不是独立协议——`isMock: true` 时工厂把任意协议都路由到 DemoAdapter，
7 个协议走同一条链路，唯一差异是 `DeviceConfig` 的占位字段结构
（已由 deviceConfig 注册表的 `mockPlaceholder` 覆盖）：

```
① 对话框：选「自定义数据」→ 粘贴 JSON（顶层 key = 点位 ID）→ 校验后保存
   config：{ demo: true, profile: 'custom', customData: <解析后的对象> }
② buildDeviceConfig：查注册表 → { ...mockPlaceholder, isMock: true, pollIntervalMs,
   profile: 'custom', customData }          ← 7 协议统一（差异仅占位字段）
③ IPC gateway_connect → Rust factory 见 isMock → DemoAdapter::new(Custom, customData)
④ 每个轮询周期：订阅点位拿到 JSON 中「以自己点ID 为 key」的 value；key 缺失 → null
⑤ 节点绑定点位时填写的点ID = JSON key，各点各取各值
```

## 4. 绑定页三分行为（v2 修订）

| 场景 | 点ID 区 | 行为 |
|---|---|---|
| 0 未选数据源 | **整体隐藏** | 仅剩数据源下拉 |
| 1 演示波形档 | 完整编辑区（添加/导入/画面点） | 点组为空时自动插入默认组：pointId=`sample-point`（只读，删除按钮保留），名称/转换/备注选填；额外点组**正常写入存档**，运行期无数据 |
| 2 演示自定义档 | 完整编辑区 | 点组为空时自动插入空点组；提示按 JSON 顶层 key 填点ID；key chips 快捷添加；key 缺失黄色警告；提交走草稿原路径 |

运行期取值（Rust DemoAdapter）：

- 波形档：仅 `sample-point` 生成波形值，其余点位返回 null（write 覆盖优先）；
- 自定义档：以点ID 为 key 取 customData 对应值，key 缺失/非对象 → null。

节点侧消费：点位值即对应 JSON 值或波形值，节点经既有 transform 函数提取字段，无需新通道。

## 7. 边界约定

- custom 档但 customData 为空/非法 → 前端保存校验拦截（选了自定义数据必须填合法 JSON 对象）。
- 运行期 key 缺失 / customData 非对象 → Rust 返回 null，前端不崩溃（语义安全）。
- 演示模式 write 覆盖优先级不变（写入值优先于波形/自定义数据）。

## 8. v3 修订（2026-08-20）：移除遗留默认点ID + 复制节点独立

背景：

- `nodeTemplates.ts` 的 `pointIdTemplate`（sensor.temp、device.* 等）与 `buildNodeConfig` 自动注入 `data.pointId` + `binding.points`（含 transform）是旧演示时代（任意点ID 可出数）的遗留；新演示点位语义（波形档 sample-point / 自定义档 JSON key）下已失去意义。
- 复制粘贴（Ctrl+C/V/D）直接继承源节点 `pointId` 与 `binding`（含 sourceId），第二个节点被第一个节点的配置影响。

1. `components/nodes/nodeTemplates.ts`：

   - 货架 `buildData` 改无参（不再注入 pointId/binding，保留初始 floorGrids）；
   - `buildNodeConfig` 不再生成 pointId、不再注入 binding，仅产出形状/尺寸/样式/data；不再依赖 Graph 参数。

## 9. v4 修订（2026-08-20）：共享会话订阅引用计数（退订连坐修复）

背景（检查「两个同类型节点分别绑定不同数据源」时发现）：

- 配置不同的数据源 → serviceKey 不同 → 各自独立 `IpcGatewayService` 实例（独立 Rust 会话），遥测事件按 `deviceId` 过滤分发，**完全隔离，功能正常**。
- 配置完全相同的数据源（典型：两个默认演示正弦源，config 均为 `{demo:true, profile:'sine'}`）→ serviceKey 相同 → 共享同一服务实例（同一 Rust 会话，属合理复用）。此时若两节点绑定**相同点位**（波形档固定 `sample-point` 使该场景高发）：
  - 节点 A 解绑/改绑 → `unbindNodeData` → `IpcGatewayService.unsubscribe(pointId)` 删除该点**全部**回调并向 Rust 发 `gateway_unsubscribe` → Rust 会话将该点移出轮询集 → **节点 B 数据随之中断**（退订连坐）。

修复（逐回调退订；引用计数下沉到服务层回调列表）：

1. `services/DataService.ts`：`IDataService.unsubscribe(pointId, callback?)` 增加可选回调参数——传 callback 仅移除该回调，点位无任何订阅者时才真正退订；不传保持原语义（移除该点全部回调）。
2. `services/IpcGatewayService.ts`：`unsubscribe` 按上述语义实现——仍有其他回调时不向 Rust 发 `gateway_unsubscribe`（会话轮询集不受影响）。重复 `gateway_subscribe` 在 Rust 会话中幂等，订阅侧无需计数。
3. `composables/useDataService.ts`：新增 `nodeDataCallbacks` 映射（节点 → 已登记回调）；`bindNodeData` 登记、`unbindNodeData` / `unbindAllNodes` 逐回调退订。之所以不用「退订前查其他节点引用」的方案：跳过退订会遗留孤儿回调（改绑累积重复回调、已删节点继续触发事件评估）；逐回调移除彻底无残留。
4. 新增回归测试 `composables/__tests__/nodeDataSourceIsolation.test.ts`（3 例）：
   - 不同配置数据源：两个独立服务实例，点位 ID 相同也不串数据，解绑其一不影响另一节点；
   - 相同配置共享会话、绑不同点位：各自独立收数；
   - 相同配置共享会话、绑相同点位：解绑其一另一节点继续收数，全部解绑后才退订（修复前此例失败，实证缺陷存在）。
5. 验证：vitest 72/72、vue-tsc、vite build 全部通过；cargo 侧无改动。
