# 演示模式自定义数据方案

> 状态：已实施（2026-08-20；cargo test --workspace、vitest 64/64、vue-tsc、vite build 全部通过）
> 范围：数据源管理（演示模式）新增「自定义数据」档位；演示模式点位语义调整

## 1. 背景与目标

- 数据源管理的演示模式目前仅支持四种内置波形（sine / randomWalk / sawtooth / steps）。
- 需求：新增「自定义数据」选项，用户输入 JSON 格式数据（本期仅 JSON，后续扩展其他格式），演示引擎按点位分发该数据。
- 同步调整：演示模式**波形档**的点位 ID 固定为 `sample-point`，不再使用绑定时用户自填的点 ID；**自定义数据档**不使用 sample-point，点位 ID 即 JSON 顶层 key。

## 2. 现状盘点

Rust 侧已具备（含测试）：

- `gateway-core/config.rs`：7 个协议配置均带 `profile`（含 `DemoProfile::Custom`）与 `custom_data: Option<serde_json::Value>` 字段 + `demo_custom_data()` 访问器。
- `gateway-demo/lib.rs`：`DemoAdapter` 支持 Custom 档位（当前语义：整份 JSON 返回所有点位 → **本方案改为按 key 取值**）。
- `src-tauri/src/factory.rs`：`isMock` 时统一路由 `DemoAdapter::new(profile, custom_data)`。
- 前端 `IpcGatewayService.ts` 的 `DeviceConfig` 类型已含 `customData` 与 `'custom'`。

前端缺口：

1. `platform/deviceConfig.ts`：`DemoWave` 不含 `'custom'`，演示分支不下发 `customData`。
2. `DataSourceDialog.vue`：无自定义数据录入 UI（JSON 文本框 + 校验）。
3. `protocolConfigRegistry.buildDataSourceConfig`：保存的 config 不带 `customData`。
4. 绑定侧无演示模式点位语义（固定 sample-point / 按 key 绑定）。

## 3. 各协议流程（七协议完全统一）

演示模式不是独立协议——`isMock: true` 时工厂把任意协议都路由到 DemoAdapter，
7 个协议走同一条链路，唯一差异是 `DeviceConfig` 的占位字段结构
（已由 deviceConfig 注册表的 `mockPlaceholder` 覆盖）：

```
① 对话框：选「自定义数据」→ 粘贴 JSON（顶层 key = 点位 ID）→ 校验后保存
   config：{ demo: true, profile: 'custom', customData: <解析后的对象> }
② buildDeviceConfig：查注册表 → { ...mockPlaceholder, isMock: true, pollIntervalMs,
   profile: 'custom', customData }          ← 7 协议统一（差异仅占位字段）
③ IPC gateway_connect → Rust factory 见 isMock → DemoAdapter::new(Custom, customData)
④ 每个轮询周期：订阅点位拿到 JSON 中「以自己点ID 为 key」的 value；key 缺失 → null
⑤ 节点绑定点位时填写的点ID = JSON key，各点各取各值
```

## 4. 演示模式两分行为

| | 波形档（sine/randomWalk/sawtooth/steps/缺省） | 自定义数据档（custom） |
|---|---|---|
| 点位 ID | 固定 `sample-point` | 用户填写，须与 customData 顶层 key 对应 |
| 绑定 UI | 只读卡片「演示模式固定点位：sample-point」，隐藏点组编辑/导入 | 正常点组编辑；customData 顶层 key 以可点击 chips 展示，点击即添加对应点组 |
| updateBinding | 短路提交 `[{pointId:'sample-point'}]` | 按草稿正常提交（与真实模式同路径） |
| Rust 取值 | 按点ID 生成波形（现状，不改） | `custom_data.get(point_id)`，缺失 → null |

节点侧消费：点位值即对应 key 的 JSON 值，节点经既有 transform 函数提取字段
（例：`(raw) => raw.status`），无需新通道。

## 5. 改动清单

### Rust

- `gateway-demo/src/lib.rs`：Custom 分支改按 key 取值
  （`self.custom_data.get(point_id).cloned().unwrap_or(Value::Null)`）；
  改写既有「全点同一份文档」测试为按 key 分发用例（a→1、b→对象、缺失→null；write 覆盖仍优先）；
  非对象 customData（数组/标量）时所有点得 null。
- `gateway-core/src/config.rs`：`custom_data` 字段注释与 `DemoProfile::Custom` 文档同步
  （「每轮原样返回给所有点位」→「按点ID 取对应 key 的值」）。

### 前端

- `platform/deviceConfig.ts`：
  - `normalizeDemoWave` 放行 `'custom'`（编辑回填不被丢弃）；
  - 演示分支在 `profile === 'custom'` 且 `cfg.customData` 存在时下发 `customData`；
  - 导出 `DEMO_SAMPLE_POINT_ID = 'sample-point'`；
  - `DEMO_WAVE_OPTIONS` 保持四档波形不变（custom 不是"波形"，不进波形帮助气泡）。
- `components/dataSource/protocolConfigRegistry.ts`：
  `buildDataSourceConfig` 公共字段处：custom 时写入解析后的 `customData`，非 custom 剥除残留。
- `components/DataSourceDialog.vue`：
  - 「演示波形」下拉追加「自定义数据（JSON）」选项；
  - 选中展开 JSON 多行编辑框 + 校验（必须合法 JSON 且顶层为对象，key 即点位 ID），解析失败禁止保存；
  - placeholder 示例：`{ "temp": 25.3, "status": "running" }`；
  - 波形样例小图在 custom 时隐藏；
  - 编辑回填 `JSON.stringify(customData, null, 2)`。
- `composables/useNodeBinding.ts`：
  - `demoKind` computed：非 demo → null；demo 且 profile='custom' → 'custom'；其余 → 'wave'；
  - `updateBinding`：'wave' 短路提交固定点位 `sample-point`；'custom' 走草稿原路径；
  - `assistantEntry`：demo（两档）一律 null（S7 演示不弹地址助手）；
  - `customDataKeys` computed：'custom' 档返回 customData 顶层 key 列表（供 chips 与校验提示）；
  - `watchFieldOptions`：'wave' 档返回唯一选项 `sample-point`。
- `components/propertyPanel/NodeBindingTab.vue`：
  - 'wave' 档：只读固定点位卡片；
  - 'custom' 档：点组可编辑 + key chips 快捷添加 + 点ID 不在 keys 中时黄色警告（不拦截，Rust 侧返回 null 语义安全）。

## 7. 边界约定

- custom 档但 customData 为空/非法 → 前端保存校验拦截（选了自定义数据必须填合法 JSON 对象）。
- 运行期 key 缺失 / customData 非对象 → Rust 返回 null，前端不崩溃（语义安全）。
- 演示模式 write 覆盖优先级不变（写入值优先于波形/自定义数据）。
