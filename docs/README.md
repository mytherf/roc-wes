## 文档分工与维护约定

- **README.md（根）**：门面摘要，只讲「是什么 + 怎么跑起来」，细节一律链接到 docs/。
- **用户手册**：只讲使用，不出现源码路径；协议相关的深入内容链接到对应数据源手册。
- **开发指南**：跨模块的机制与流程；单协议的实现细节在各协议「开发手册」里。
- **数据源手册**：每协议两份，用户 / 开发视角分离；新协议落地时必须同步补齐两份手册。
- **架构图**：mermaid 源文件与 PNG 同名同目录，改图时两者同步更新。
- **同步规则**：涉及命令、端口、协议支持范围的代码变更，必须同步更新本目录受影响文档（验收基线：`docs/` 内不出现已删除的目录、脚本或端口）。

## 统一规划（路线图）

以 [Tauri 目标架构 · 第 8 节](./tauri-目标架构.md#8-当前实现状态与后续路线) 为准，当前快照：

### 已完成

- IPC-first 桌面架构：Cargo workspace（core / engine / modbus / demo）+ Tauri 壳 + 前端平台接缝
- Modbus TCP 桌面直连（tokio-modbus）、全协议演示模式（DemoAdapter）
- 引擎会话机制：轮询下限 200ms、失败指数退避重连（2s→30s）、状态事件去抖
- 监控探针桌面适配（`mon:` 独立会话）、集成测试与 clippy 零警告基线
- 代码清理：Node 网关与工业 mock 桥接退役、依赖精简、S7 slot 默认值统一
- 应用图标与 NSIS 打包配置、`npx tauri dev` 开发链路
- 持久化升级：tauri-plugin-fs 全部工程数据落盘为应用配置目录 JSON 文件（原子写入），全面替代 localStorage / sessionStorage

### 后续（按风险排序）

1. **S7 spike**（风险最高）：snap7 绑定 vs 自研 S7comm（已有 TPKT/COTP/S7 PDU 的 JS 逆向经验可移植），产出 `gateway-s7` 并在 factory 注册
2. **OPC UA**：引入 `opcua` crate，产出 `gateway-opcua`
3. **打包完善**：NSIS 安装器调优、（可选）tauri-plugin-updater 自动更新
4. **日志落盘**：tracing-appender 滚动文件（AppData）

### 已知限制（现状声明）

- 浏览器版生产环境无内置数据后端（mock 仅 dev 生效），ws/http/sse/mqtt 需外部服务；工业协议浏览器模式需自备外部 WS 网关。
- 桌面版真实模式目前仅 Modbus 可用；S7 / OPC UA 连接会返回「适配器待实现」错误（演示模式不受影响）。
